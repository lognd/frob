# CI014 gha-syntax-and-schema

A workflow that breaks the GitHub Actions syntax.

## What it does

Fires for the structural errors actionlint always reports: no `on:`, no jobs, a job with neither `runs-on` nor `uses`, a job with no steps, a reusable-workflow call that also has `steps`, and a step with neither or both of `run` and `uses`. It never judges runner labels, expressions or the schema of an action's inputs; a bound actionlint stage covers those and replaces this finding.

## Why it matters

GitHub rejects or silently skips a malformed workflow, so the checks it was meant to run never happen.

## Remedy

Fix the structure the message names.

## Examples

### Fires case 1

```yaml expect=fire file=.github/workflows/ci.yml
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    steps:
      - run: echo hi
```

### Fires case 2

```yaml expect=fire file=.github/workflows/ci.yml
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: nothing
```

### Clean case 3

```yaml expect=clean file=.github/workflows/ci.yml
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo hi
```

### Clean case 4

```yaml expect=clean file=.github/workflows/ci.yml
name: ci
on: push
permissions:
  contents: read
jobs:
  call:
    uses: acme/shared/.github/workflows/build.yml@aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
```
