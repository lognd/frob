# CI012 ci-config-consistency

CI configuration that disagrees with the repository manifests and ownership files.

## What it does

Joins the workflows with the manifests. Fires when a step installs a Rust toolchain different from the `rust-toolchain.toml` channel; when a numeric toolchain (step or matrix) is older than the highest `rust-version` of the Cargo manifests; when the ecosystems the manifests imply have no Dependabot `updates` entry (Renovate configuration skips this check); or when a present CODEOWNERS has no entry covering `.github`.

## Why it matters

CI that tests a different toolchain than the repository pins, ignores the declared minimum Rust version, never updates its dependencies or lets anyone change the workflows gives green results that mean less than they say.

## Remedy

Align the CI toolchain with `rust-toolchain.toml` and `rust-version`, add a Dependabot `updates` entry per ecosystem, and add a CODEOWNERS entry for `/.github/`.

## Examples

### Fires case 1

```yaml expect=fire file=.github/workflows/ci.yml config="pin=1.80.0"
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: dtolnay/rust-toolchain@1.70
```

### Fires case 2

```yaml expect=fire file=.github/workflows/ci.yml config="msrv=1.70"
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        rust: ['1.60', stable]
    steps:
      - run: cargo test
```

### Fires case 3

```yaml expect=fire file=.github/workflows/ci.yml config="cargo"
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: cargo test
```

### Fires case 4

```yaml expect=fire file=.github/workflows/ci.yml config="cargo dependabot-cargo-only"
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest

      - run: cargo test
```

### Fires case 5

```yaml expect=fire file=.github/workflows/ci.yml config="dependabot owners-missing"

  build:
```
