# CI012 ci-config-consistency

CI configuration that disagrees with the repository manifests and ownership files.

## What it does

Joins the workflows with the manifests. Fires when a step installs a Rust toolchain different from the `rust-toolchain.toml` channel; when a numeric toolchain (step or matrix) is older than the highest `rust-version` of the Cargo manifests; when the ecosystems the manifests imply have no Dependabot `updates` entry (Renovate configuration skips this check); when a present CODEOWNERS has no entry covering `.github`; or when a `run:` script invokes a `frob` verb (or first subcommand) that frob does not have. The verb scan is lexical: it reads simple commands, skips comments, heredoc bodies, `NAME=value` prefixes, `sudo`/`env`-style wrappers and quotes, and does not judge a verb built from a variable or expression.

## Why it matters

A workflow that calls a verb frob lacks fails only when it runs, often on a branch nobody watches. CI that tests a different toolchain than the repository pins, ignores the declared minimum Rust version, never updates its dependencies or lets anyone change the workflows gives green results that mean less than they say.

## Remedy

Align the CI toolchain with `rust-toolchain.toml` and `rust-version`, add a Dependabot `updates` entry per ecosystem, and add a CODEOWNERS entry for `/.github/`, and fix or remove a `frob` verb that does not exist (the finding lists the valid ones).

## Examples

### Fires case 1

```yaml expect=fire file=.github/workflows/ci.yml config="pin=1.80.0"
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: dtolnay/rust-toolchain@1.70
```

### Fires case 2

```yaml expect=fire file=.github/workflows/ci.yml config="msrv=1.70"
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        rust: ['1.60', stable]
    steps:
      - run: cargo test
```

### Fires case 3

```yaml expect=fire file=.github/workflows/ci.yml config="cargo"
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: cargo test
```

### Fires case 4

```yaml expect=fire file=.github/workflows/ci.yml config="cargo dependabot-cargo-only"
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: cargo test
```

### Fires case 5

```yaml expect=fire file=.github/workflows/ci.yml config="dependabot owners-missing"
name: ci

  build:
```

### Fires case 8

```yaml expect=fire file=.github/workflows/ci.yml config="dependabot"

on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest

```

### Clean case 9

```yaml expect=clean file=.github/workflows/ci.yml config="dependabot"
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: |
          # frob nonsense in a comment
          FROB_LOG=1 frob --format json ticket show T-1 | jq .
          echo "frob nonsense" && frob check --help
```
