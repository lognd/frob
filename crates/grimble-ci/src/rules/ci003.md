# CI003 ci-permissions-write-all

Top-level permissions that grant write to every job.

## What it does

Fires when the top-level `permissions` is `write-all` or any scope is `write`.

## Why it matters

Every job inherits the top-level grant, including jobs that run untrusted code.

## Remedy

Set the top level to `contents: read` and give the single job that needs write its own `permissions`.

## Examples

### Fires case 1

```yaml expect=fire file=.github/workflows/ci.yml
name: ci
on: push
permissions: write-all
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo hi
```

### Fires case 2

```yaml expect=fire file=.github/workflows/ci.yml
name: ci
on: push
permissions:
  contents: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo hi
```

### Clean case 3

```yaml expect=clean file=.github/workflows/ci.yml
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - run: echo hi
```
