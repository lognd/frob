# DK001 dk-root-user

A final image stage that runs as root.

## What it does

Fires when the final build stage never sets `USER`, or its last `USER` is `root` or `0`. Inheritance through an earlier internal stage is followed; a `scratch` final stage is skipped.

## Why it matters

A process that escapes the container as root is root on the host's namespace boundary; most services need no root.

## Remedy

Create an unprivileged user and switch to it before the entrypoint: `RUN useradd -r app` then `USER app`.

## Examples

### Fires case 1

```dockerfile expect=fire file=Dockerfile
FROM debian:12
RUN apt-get update
CMD ["app"]
```

### Fires case 2

```dockerfile expect=fire file=Dockerfile
FROM debian:12
USER root
CMD ["app"]
```

### Clean case 3

```dockerfile expect=clean file=Dockerfile
FROM debian:12
RUN useradd -r app
USER app
CMD ["app"]
```

### Clean case 4

```dockerfile expect=clean file=Dockerfile
FROM debian:12 AS base
USER 1000:1000
FROM base
CMD ["app"]
```
