# CI008 ci-publish-untagged

A registry publish on a trigger that is not limited to release tags.

## What it does

Fires for a step that publishes to a registry (`cargo publish`, `npm publish`, `twine upload`, `uv publish`, `gem push`, `docker push`, `nuget push`, `pypa/gh-action-pypi-publish`) in a workflow triggered by `pull_request`, `pull_request_target` or a `push` without a `tags` filter. A job or step `if` that mentions `refs/tags` silences it.

## Why it matters

A publish that runs on every push or on untrusted pull requests releases unreviewed code or leaks the registry credential.

## Remedy

Trigger on `push: tags: ['v*']` or `release`, or gate the step with `if: startsWith(github.ref, 'refs/tags/')`.

## Examples

### Fires case 1

```yaml expect=fire file=.github/workflows/ci.yml
name: release
on:
  push:
    branches: [main]
permissions:
  contents: read
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - run: cargo publish
```

### Clean case 2

```yaml expect=clean file=.github/workflows/ci.yml
name: release
on:
  push:
    tags: ['v*']
permissions:
  contents: read
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - run: cargo publish
```

### Clean case 3

```yaml expect=clean file=.github/workflows/ci.yml
name: release
on:
  push:
    branches: [main]
permissions:
  contents: read
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - if: startsWith(github.ref, 'refs/tags/')
        run: cargo publish
```
