# CI001 pinned-ref

An external `uses:` that is not pinned to a full commit SHA.

## What it does

Fires for every step or job `uses:` that names an external action or reusable workflow whose ref is not a 40-hex commit SHA, including a missing ref and a `docker://` image without `@sha256:`. Local `./path` actions are skipped, and so are owners listed in `allow_tag_pins_for`.

## Why it matters

A tag or branch can be moved by whoever controls the action repository, so a compromised release runs inside your workflow with its token.

## Remedy

Pin the action to its commit SHA and keep the version in a trailing comment; Dependabot or Renovate bumps both together.

## Examples

### Fires case 1

```yaml expect=fire file=.github/workflows/ci.yml
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
```

### Clean case 2

```yaml expect=clean file=.github/workflows/ci.yml
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa # v4
```

### Clean case 3

```yaml expect=clean file=.github/workflows/ci.yml
name: ci
on: push

  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: ./.github/actions/setup
```

### Clean case 4

```yaml expect=clean file=.github/workflows/ci.yml config="allow-tag-pins=actions"
name: ci

  contents: read

  build:
```
