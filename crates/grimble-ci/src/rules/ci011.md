# CI011 ci-pr-target-permissions

A pull_request_target workflow without explicit read-only permissions.

## What it does

Fires when a workflow triggers on `pull_request_target` and lacks top-level `permissions` (with a job that has none either), or any workflow or job permission grants write.

## Why it matters

`pull_request_target` runs in the base repository context with a privileged token while handling untrusted pull request input.

## Remedy

Add `permissions: contents: read` to the workflow and every job, and never check out the pull request head with a write token.

## Examples

### Fires case 1

```yaml expect=fire file=.github/workflows/ci.yml
name: triage
on: pull_request_target
jobs:
  label:
    runs-on: ubuntu-latest
    steps:
      - run: echo hi
```

### Clean case 2

```yaml expect=clean file=.github/workflows/ci.yml
name: triage
on: pull_request_target
permissions:
  contents: read
jobs:
  label:
    runs-on: ubuntu-latest
    steps:
      - run: echo hi
```
