# CI004 ci-concurrency-missing

A push or pull request workflow with no concurrency group.

## What it does

Fires when a workflow triggers on `push` or `pull_request` and neither the workflow nor every job sets `concurrency`.

## Why it matters

Superseded runs keep consuming minutes and can race each other on shared resources.

## Remedy

Add `concurrency: { group: ${{ github.workflow }}-${{ github.ref }}, cancel-in-progress: true }`.

## Examples

### Fires case 1

```yaml expect=fire file=.github/workflows/ci.yml
name: ci
on: pull_request
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo hi
```

### Clean case 2

```yaml expect=clean file=.github/workflows/ci.yml
name: ci
on: pull_request
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo hi
```

### Clean case 3

```yaml expect=clean file=.github/workflows/ci.yml
name: nightly
on:
  schedule:
    - cron: '0 3 * * *'
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo hi
```
