# CI009 ci-publish-token

A long-lived token used to publish where trusted publishing exists.

## What it does

Fires when a job publishes to crates.io, npm, PyPI or RubyGems with a `secrets.*` name containing TOKEN, KEY or PASSWORD and neither the job nor the workflow grants `id-token: write`.

## Why it matters

A stored token can leak and never expires; trusted publishing exchanges a short-lived OIDC token instead.

## Remedy

Register a trusted publisher with the registry and add `permissions: id-token: write` to the publish job.

## Examples

### Fires case 1

```yaml expect=fire file=.github/workflows/ci.yml
name: release
on:
  push:
    tags: ['v*']
permissions:
  contents: read
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - run: cargo publish
        env:
          CARGO_REGISTRY_TOKEN: ${{ secrets.CARGO_TOKEN }}
```

### Clean case 2

```yaml expect=clean file=.github/workflows/ci.yml
name: release
on:
  push:
    tags: ['v*']
permissions:
  contents: read
jobs:
  publish:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
    steps:
      - run: cargo publish
        env:
          CARGO_REGISTRY_TOKEN: ${{ secrets.CARGO_TOKEN }}
```
