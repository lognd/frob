# CI002 ci-permissions-missing

A workflow without top-level permissions where a job sets none.

## What it does

Fires when a workflow has no top-level `permissions` key and at least one job has no `permissions` of its own. The message gives the remedy: add `permissions: contents: read` at the top.

## Why it matters

Without `permissions` the `GITHUB_TOKEN` gets the repository default, which is often read-write. A compromised step then holds write access it never needed.

## Remedy

Add `permissions: contents: read` at the workflow top and widen it per job only where a job needs more.

## Examples

### Fires case 1

```yaml expect=fire file=.github/workflows/ci.yml
name: ci
on: push
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo hi
```

### Clean case 2

```yaml expect=clean file=.github/workflows/ci.yml
name: ci
on: push
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo hi
```

### Clean case 3

```yaml expect=clean file=.github/workflows/ci.yml
name: ci
on: push
jobs:
  build:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - run: echo hi
```
