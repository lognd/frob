# CI013 no-secrets-inherit

A call to an external reusable workflow that passes every secret.

## What it does

Fires for a job that calls a reusable workflow outside the repository (`uses: owner/repo/.github/workflows/x.yml@ref`) with `secrets: inherit`. A local `./` workflow, an explicit secret mapping and an expression value are not judged. A bound zizmor `secrets-inherit` finding replaces this one.

## Why it matters

`secrets: inherit` hands the callee every secret the caller can see, including ones it does not need; a compromised or malicious callee can read them all.

## Remedy

Pass the secrets the callee needs by name under `secrets:`.

## Examples

### Fires case 1

```yaml expect=fire file=.github/workflows/ci.yml
name: ci
on: push
permissions:
  contents: read
jobs:
  call:
    uses: acme/shared/.github/workflows/build.yml@aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
    secrets: inherit
```

### Clean case 2

```yaml expect=clean file=.github/workflows/ci.yml
name: ci
on: push
permissions:
  contents: read
jobs:
  call:
    uses: acme/shared/.github/workflows/build.yml@aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
    secrets:
      token: ${{ secrets.TOKEN }}
```

### Clean case 3

```yaml expect=clean file=.github/workflows/ci.yml
name: ci
on: push
permissions:
  contents: read
jobs:
  call:
    uses: ./.github/workflows/build.yml
    secrets: inherit
```
