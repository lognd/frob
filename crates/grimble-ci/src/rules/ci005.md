# CI005 ci-timeout-missing

A job with no timeout-minutes, or one above the configured limit.

## What it does

Fires for every job (reusable-workflow calls excepted) with no `timeout-minutes`, or a numeric one above `max_timeout` (default 60). Expression values are not judged.

## Why it matters

A hung step otherwise runs for the six hour default and holds a runner the whole time.

## Remedy

Add `timeout-minutes` with a bound a little above the measured run time.

## Examples

### Fires case 1

```yaml expect=fire file=.github/workflows/ci.yml
name: ci
on: push
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo hi
```

### Fires case 2

```yaml expect=fire file=.github/workflows/ci.yml
name: ci
on: push
jobs:
  build:
    runs-on: ubuntu-latest
    timeout-minutes: 300
    steps:
      - run: echo hi
```

### Clean case 3

```yaml expect=clean file=.github/workflows/ci.yml
name: ci
on: push
jobs:
  build:
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      - run: echo hi
```

### Clean case 4

```yaml expect=clean file=.github/workflows/ci.yml
name: ci
on: push
jobs:
  call:
    uses: ./.github/workflows/other.yml
```
