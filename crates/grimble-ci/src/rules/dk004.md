# DK004 dk-pipe-to-shell

A download piped straight into a shell.

## What it does

Fires for a shell-form `RUN` where `curl` or `wget` output is piped into `sh`, `bash`, `zsh`, `dash` or `ash`, or substituted with `sh -c "$(curl ...)"` or `bash <(curl ...)`. Downloads from a host in `allow_pipe_hosts` are allowed.

## Why it matters

The script runs unverified; a compromised host or a truncated download runs partial or hostile code as the build user.

## Remedy

Download to a file, verify a checksum or signature, then run it.

## Examples

### Fires case 1

```dockerfile expect=fire file=Dockerfile
FROM debian:12
RUN curl -fsSL https://example.com/install.sh | sh
USER app
```

### Fires case 2

```dockerfile expect=fire file=Dockerfile
FROM debian:12
RUN sh -c "$(curl -fsSL https://example.com/i.sh)"
USER app
```

### Clean case 3

```dockerfile expect=clean file=Dockerfile
FROM debian:12
RUN curl -fsSLO https://example.com/install.sh && sha256sum -c install.sh.sha256 && sh install.sh
USER app
```

### Clean case 4

```dockerfile expect=clean file=Dockerfile config="allow=sh.rustup.rs"
FROM debian:12
RUN curl -fsSL https://sh.rustup.rs | sh
USER app
```
