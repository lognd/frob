# DUP003 arch-clone-index

The clone index of DUP001 is missing or damaged.

## What it does

`DUP001` keeps the window hashes of every file in a content-addressed index under the git common directory (`<common>/frob/dup-index`), shared by the primary checkout and all linked worktrees. The index is built on the first check and afterwards updated only for files whose content changed. `DUP003` fires once, anchored at the first examined file, when the index directory exists but its manifest is absent or foreign, an entry is truncated or fails its checksum, or the store cannot be written. The rule fails closed: while it fires, `DUP001` is not evaluated, so a damaged index can never hide a clone. Outside a git checkout there is no index and the rule cannot fire.

## Why it matters

Silently recomputing over a damaged cache would hide the damage and could mask a stale or tampered entry that makes `DUP001` miss a copy.

## Remedy

Delete the directory named in the message; the next check rebuilds it.

## Examples

### Fires case 1

```text expect=fire file=.git/frob/dup-index/MANIFEST
not a dup index
```

```rust file=src/lib.rs
pub fn answer() -> i64 {
    42
}
```

### Clean case 2

```rust expect=clean file=src/lib.rs
pub fn answer() -> i64 {
    42
}
```
