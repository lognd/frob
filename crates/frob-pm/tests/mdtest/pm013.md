# PM013 WIP limit exceeded

Each block is a small ledger. `limit N` sets `[pm.wip] in_progress`;
`task KEY` creates a ticket and `task KEY state=in_progress` moves it
into progress.

## Three in progress with limit 2 fires naming the holders

```text expect=fire
limit 2
task a state=in_progress
task b state=in_progress
task c state=in_progress
```

## Two in progress with limit 2 is clean

```text expect=clean
limit 2
task a state=in_progress
task b state=in_progress
```

## Tickets not in progress do not count

```text expect=clean
limit 1
task a state=in_progress
task b
task c
```

## A limit of 0 is off

```text expect=clean
limit 0
task a state=in_progress
task b state=in_progress
```

## Expedite holders are exempt from the repository limit

Two standard holders fill the limit; the expedite ticket sits in its own
lane (`expedite_max` defaults to 1).

```text expect=clean
limit 2
task a state=in_progress
task b state=in_progress
task hot state=in_progress class=expedite
```

## Standard holders over the limit still fire beside an expedite one

```text expect=fire
limit 2
task a state=in_progress
task b state=in_progress
task c state=in_progress
task hot state=in_progress class=expedite
```

## Expedite lane over expedite_max fires

```text expect=fire
limit 5
expedite_max 1
task hot1 state=in_progress class=expedite
task hot2 state=in_progress class=expedite
```

## A closed expedite lane counts expedite like standard

```text expect=fire
limit 2
expedite_max 0
task a state=in_progress
task b state=in_progress
task hot state=in_progress class=expedite
```

## Stale in-progress tickets (lease expired) do not count

```text expect=clean
limit 2
task a state=in_progress
task b state=in_progress
task old state=in_progress stale
```

## Stale tickets do not hide live holders over the limit

```text expect=fire
limit 1
task a state=in_progress
task b state=in_progress
task old state=in_progress stale
```
