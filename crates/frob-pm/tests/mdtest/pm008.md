# PM008 ticket aging per category

Each block is a small ledger. `later_days N` moves the clock N days past
now; `max_age_in_progress N` and `max_age_ready N` set `[pm.max_age_days]`
(0 is off). A ticket ages from its latest move into its current category.

## In progress past the limit fires with the age

```text expect=fire
later_days 5
task a state=in_progress
```

## In progress within the limit is silent

```text expect=clean
later_days 2
task a state=in_progress
```

## A zero in-progress limit is off

```text expect=clean
later_days 40
max_age_in_progress 0
task a state=in_progress
```

## A ready ticket past its limit fires

```text expect=fire
later_days 31
task a points=1
```

## A ready ticket within its limit is silent

```text expect=clean
later_days 10
task a points=1
```

## Epics do not age

```text expect=clean
later_days 90
epic e
```

## Unresolved when the ledger cannot be read

`unreadable` corrupts the ticket index after the ledger is built, so the rule cannot judge and reports the required Unresolved.

```text expect=unresolved
task a
unreadable
```
