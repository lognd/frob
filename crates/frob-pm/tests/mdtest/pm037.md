# PM037 design obligation without an implementing ticket

The fixed design graph has two declared impls, `impl/a.b` and `impl/a.c`,
each with an unbound obligation. `implements=ANCHOR` links a ticket to
`design:ANCHOR`. The rule stays silent until some ticket uses `implements`.

## A repo that never uses implements is clean

```text expect=clean
task a
```

## An obligation with no ticket fires on its anchor

```text expect=fire
task a implements=design:impl/a.b
```

## Every obligation planned is clean

```text expect=clean
task a implements=design:impl/a.b
task b implements=design:impl/a.c
```
