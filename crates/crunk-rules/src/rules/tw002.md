# TW002 theme-entry-undefined-token

A Tailwind theme entry may only map to a token that exists. Each block is one source file in a
project whose `crunk.toml` is the default preset plus `[tailwind] config`; the examples run against
a stand-in theme.

## What it does

Flags a theme entry whose value is exactly `var(--name)` when `--name` is neither in the spec's
token export nor defined by an ingested sheet. The theme has no per-entry location, so the finding
sits at the start of `[tailwind] config`. When a definition source was not indexed the name is
Unresolved rather than a finding. With no `[tailwind] config` the rule is inapplicable.

## Why it matters

A theme entry pointing at a token nobody defines compiles to a colour that does not resolve: the
class applies and renders as nothing.

## Remedy

Define the token (in the spec) or point the entry at one that exists.

## Examples

### A theme entry mapped to an undefined token fires

```css expect=fire config=tw-theme-broken file=styles/app.css
.a {
  margin: 0;
}
```

### A theme entry that is a literal is clean

```css expect=clean config=tw-theme-plain file=styles/app.css
.a {
  margin: 0;
}
```
