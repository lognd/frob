# ORG003 component-prefix

Classes in `components/<name>.css` carry the component name. Each block is one source file in a
project whose `crunk.toml` is the default preset (`component_prefix = true`).

## What it does

In a `components` bucket sheet named `<name>.css`, flags every class that is not `<name>`,
`<name>__*` or `<name>--*`. Silent, and reported as inapplicable, when `[org] model` is
`utility-first` or `[org] component_prefix` is off.

## Why it matters

The prefix is what lets a component file own its classes: a generic `.title` in `card.css` collides
with every other `.title` in the project.

## Remedy

Rename the class to start with the component name, or move it to the bucket that owns it.

## Examples

### A class without the component prefix fires

```css expect=fire file=styles/components/card.css
.title {
  margin: 0;
}
```

### A class of another component fires

```css expect=fire file=styles/components/card.css
.button__label {
  margin: 0;
}
```

### The component, its elements and its modifiers are clean

```css expect=clean file=styles/components/card.css
.card {
  margin: 0;
}
.card__title {
  margin: 0;
}
.card--wide {
  margin: 0;
}
```

### Other buckets carry no prefix rule

```css expect=clean file=styles/layouts/stack.css
.title {
  margin: 0;
}
```
