# I18N002 rtl-physical-direction

A project that ships a right-to-left locale styles with logical start/end, not physical left/right.

## What it does

When a content file declares a right-to-left locale (Arabic, Hebrew, Persian, Urdu and the like), fires once per stylesheet that uses a physical property (`margin-left`, `padding-right`, `left`, `border-right`), a physical `text-align`, `float` or `clear` value, or a physical Tailwind utility (`ml-4`, `pr-2`, `text-left`). A project with no right-to-left locale passes.

## Why it matters

Physical sides do not flip with the text direction, so the right-to-left layout keeps its gutters, icons and alignment on the wrong side.

## Remedy

Use the logical form: `margin-inline-start`, `padding-inline-end`, `inset-inline-start`, `text-align: start`, or the Tailwind `ms-`, `pe-`, `start-` and `text-start` utilities.

## Examples

### A physical margin beside a Hebrew locale fires

```css expect=fire file=styles/app.css config=i18n-rtl
.card { margin-left: 8px; }
```

### A logical margin is clean

```css expect=clean file=styles/app.css config=i18n-rtl
.card { margin-inline-start: 8px; }
```
