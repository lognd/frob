# TW004 tailwind-default-color

A colour utility must come from the project theme, not Tailwind's defaults. Each block is one source
file in a project whose `crunk.toml` is the default preset; the examples run against a stand-in for
the project's Tailwind.

## What it does

Flags a utility whose colour part is one of Tailwind's default colour names (`bg-red-500`,
`text-black/10`, alpha modifier stripped first) that the project theme does not define, when the
colour Tailwind compiles it to is that default's own rgb. A name the theme overrides is clean, and a
compiled colour that is not the default's (the theme redefined it elsewhere) is exempt. `transparent`,
`current` and `inherit` are not default colour names. A utility Tailwind could not answer for is
Unresolved.

## Why it matters

`bg-red-500` works on every machine and belongs to nobody's design: it bypasses the palette without
a single off-palette literal in the source.

## Remedy

Use a theme colour, or define the name in the theme.

## Examples

### A default colour name fires

```tsx expect=fire file=src/Card.tsx
export const Card = () => <div className="bg-red-500" />;
```

### An alpha-modified default colour fires

```tsx expect=fire file=src/Card.tsx
export const Card = () => <div className="text-black/10" />;
```

### A name outside Tailwind's defaults is clean

```tsx expect=clean config=tw-theme-plain file=src/Card.tsx
export const Card = () => <div className="bg-brand" />;
```

### A non-colour utility is clean

```tsx expect=clean file=src/Card.tsx
export const Card = () => <div className="flex items-center" />;
```
