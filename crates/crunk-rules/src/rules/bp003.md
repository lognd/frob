# BP003 fixed-width-exceeds-breakpoint

A fixed width must fit the smallest declared breakpoint. Each block is one source file in a project
whose `crunk.toml` is the default preset plus `[breakpoints]` sm 640, md 768, lg 1024
(`config=breakpoints`).

## What it does

Flags a `width` or `min-width` whose px or rem value is larger than the smallest declared
breakpoint: on a viewport narrower than that, the box is guaranteed to overflow. `max-width` and
values that are not px-comparable (percentages, `auto`, `calc()`) are exempt. The family is off, and
the rule inapplicable, when no `[breakpoints]` are declared.

## Why it matters

A 700px box is fine on a laptop and a horizontal scrollbar on every phone; the declared breakpoints
already say where the layout may change.

## Remedy

Use `max-width` with a fluid `width`, or move the fixed width inside a media query at a declared
breakpoint.

## Examples

### A fixed width wider than the smallest breakpoint fires

```css expect=fire config=breakpoints file=styles/app.css
.hero {
  width: 700px;
}
```

### A min-width in rem fires

```css expect=fire config=breakpoints file=styles/app.css
.hero {
  min-width: 50rem;
}
```

### A narrow fixed width is clean

```css expect=clean config=breakpoints file=styles/app.css
.hero {
  width: 320px;
}
```

### max-width and fluid widths are exempt

```css expect=clean config=breakpoints file=styles/app.css
.hero {
  max-width: 900px;
  width: 100%;
}
```
