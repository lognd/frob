# BP002 responsive-without-base

A responsive utility needs an unprefixed base in the same class list. Each block is one source file
in a project whose `crunk.toml` is the default preset plus `[breakpoints]` sm 640, md 768, lg 1024
(`config=breakpoints`; `base_required` defaults to flex, grid, block, hidden, `w-`, `h-`, `col-`,
`row-`).

## What it does

Flags a utility whose variants include a declared breakpoint (or an arbitrary `min-[...]`) and whose
name is in a `base_required` family, when no unprefixed utility of that family sits in the same
`className` string. `flex`, `grid`, `block` and `hidden` are one family: `hidden md:flex` passes.
The family is off, and the rule inapplicable, when no `[breakpoints]` are declared.

## Why it matters

`md:flex` alone says nothing about what a phone gets: the browser default wins by accident rather
than by decision.

## Remedy

Add the unprefixed utility for the mobile layout (`block md:flex`).

## Examples

### A breakpoint variant with no base fires

```tsx expect=fire config=breakpoints file=src/Card.tsx
export const Card = () => <div className="md:flex" />;
```

### A width with a breakpoint variant and no base fires

```tsx expect=fire config=breakpoints file=src/Card.tsx
export const Card = () => <div className="md:w-1/2" />;
```

### An unprefixed base in the same class list is clean

```tsx expect=clean config=breakpoints file=src/Card.tsx
export const Card = () => <div className="block md:flex" />;
```

### The display family shares one base

```tsx expect=clean config=breakpoints file=src/Card.tsx
export const Card = () => <div className="hidden md:flex" />;
```

### A utility outside the required families is exempt

```tsx expect=clean config=breakpoints file=src/Card.tsx
export const Card = () => <div className="md:p-4" />;
```
