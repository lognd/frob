# MDL014 mdl-vmodel

A V-model construction error.

## What it does

Wrong endpoint kinds, unpaired levels on `verifies`, a test with neither `runnable` nor `manual because=".."` (or both, or an empty reason), a duplicate link, or `supersedes` without `because`.

## Why it matters

The V-model links requirements to the tests that verify them. A link with the wrong endpoints, or a test with nothing to run, verifies nothing while looking as if it does.

## Remedy

Give a test one `runnable` per runner id, or `manual because="REASON"`, an artifact a `ref`, and pair the levels on every `verifies`.

## Examples

### Fires case 1

```grmb expect=fire file=design/model.grmb
grimble = "2";
module m;
vmodel t_missing {
  kind test;
  level customer_test;
}
```

### Clean case 2

```grmb expect=clean file=design/model.grmb
grimble = "2";
module m;
vmodel req {
  kind artifact;
  level requirements;
  ref "docs/design/a.md#req";
}
vmodel t_ok {
  kind test;
  level acceptance;
  runnable "t.rs::ok";
  verifies req;
}
```

### Clean case 3

```grmb expect=clean file=design/model.grmb
grimble = "2";
module m;
vmodel t_many {
  kind test;
  level acceptance;
  runnable "t.rs::one";
  runnable "t.rs::two";
}
vmodel t_hand {
  kind test;
  level acceptance;
  manual because="needs a person at the console";
}
```

### Fires case 4

```grmb expect=fire file=design/model.grmb
grimble = "2";
module m;
vmodel t_both {
  kind test;
  level acceptance;
  runnable "t.rs::one";
  manual because="also by hand";
}
```
