# SYS015 sys-behavior-flow

A consecutive step-use pair across two nodes has no declared flow.

## What it does

For every step use followed by another in a scenario, when both sit in known, different nodes (from an impl `in node` or the actor's `node`), a `flow` from the first node to the second must be declared; direction matters. When either node is unknown the verdict is Unresolved, never clean.

## Why it matters

Behaviour that crosses a node boundary is data movement; an undeclared flow hides it from the flow and noflow checks.

## Remedy

Declare `flow NAME : X -> Y`, or move a step into the right node.

## Examples

### Fires case 1

```grmb expect=fire file=design/model.grmb
grimble = "2";
module m;
node n1 : trusted { attr stateful; }
node n2 : trusted { kind store; }


system s {
  actor a : human;
  actor b : human;
  step a.one;
  step b.two;
  scenario t {
    a.one -> b.two => { ok -> end ok; }
  }
  impl a.one for t { in node n1; }
  impl b.two for t { in node n2; }
}
```

### Clean case 2

```grmb expect=clean file=design/model.grmb
grimble = "2";
module m;
node n1 : trusted { attr stateful; }
node n2 : trusted { kind store; }

flow f : n1 -> n2 { label Internal; }
system s {
  actor a : human;
  actor b : human;
  step a.one;
  step b.two;
  scenario t {
    a.one -> b.two => { ok -> end ok; }
  }
  impl a.one for t { in node n1; }
  impl b.two for t { in node n2; }
}
```
