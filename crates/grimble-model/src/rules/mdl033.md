# MDL033 mdl-open-match

A match over an `open` outcome set has neither `unknown` nor `_`.

## What it does

A step whose outcome set is written `: open { .. }` is owned outside the model and may gain variants. A `=>` match on such a step needs an `unknown` or `_` arm. The rule reports a match with neither. A `handle` block is not read.

## Why it matters

Without a catch-all, an externally added outcome has no arm, and the match is silently incomplete (grmb-spec 15.4, D140).

## Remedy

Add an `unknown` arm (after an arm for every known variant), or a `_` arm.

## Examples

### Fires case 1

```grmb expect=fire file=design/model.grmb
grimble = "2";
module m;

system s {
  actor u : human;
  step u.go;
  step system.flaky : open { ok, bad };

  scenario t fails with { bad } {
    u.go -> system.flaky => {
      ok => end ok;
      bad => end err(bad);
    }
  }
}
```

### Clean case 2

```grmb expect=clean file=design/model.grmb
grimble = "2";
module m;

system s {
  actor u : human;
  step u.go;
  step system.flaky : open { ok, bad };

  scenario t fails with { bad } {
    u.go -> system.flaky => {
      ok => end ok;
      bad => end err(bad);
      unknown => end err(bad);
    }
  }
}
```
