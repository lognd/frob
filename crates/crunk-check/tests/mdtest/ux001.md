# UX001 route-has-screen

Every route of the sitemap must have a screen.

## What it does

With `[packs] design_cycle = true`, reads `design/ia/sitemap.toml` and flags each page whose route no
`[[screen]]` serves, either by naming it (`screen = "id"`) or by having the same route as its
`entry`. A project without a sitemap is silent, and so is one that has not switched the pack on.

## Why it matters

A route with no screen is a page nobody designed: its states, copy and focus order are guesses.

## Remedy

Author the screen (`design/screens/<id>.screen.toml`) or remove the route from the sitemap.

## Examples

### A route without a screen fires

```toml file=design/ia/sitemap.toml
[[pages]]
route = "/"
label = "Home"

[[pages]]
route = "/pricing"
label = "Pricing"
parent = "/"
```

```toml expect=fire file=crunk.toml
[packs]
design_cycle = true

[[screen]]
id = "home"
entry = "/"
[[screen.states]]
id = "default"
```

### A route with a screen is clean

```toml file=design/ia/sitemap.toml
[[pages]]
route = "/"
label = "Home"
```

```toml expect=clean file=crunk.toml
[packs]
design_cycle = true

[[screen]]
id = "home"
entry = "/"
[[screen.states]]
id = "default"
```

### A project that has not opted in is clean

```toml file=design/ia/sitemap.toml
[[pages]]
route = "/"
label = "Home"

[[pages]]
route = "/pricing"
label = "Pricing"
parent = "/"
```

```toml expect=clean file=crunk.toml
[[screen]]
id = "home"
entry = "/"
[[screen.states]]
id = "default"
```

### A sitemap that does not parse is unresolved

```toml file=design/ia/sitemap.toml
this is = not [valid
```

```toml expect=unresolved file=crunk.toml reason=sitemap-invalid
[packs]
design_cycle = true
```
