# GX014 ugui-literal-not-token

A uGUI prefab generator must take its colors and font sizes from the generated token constants,
never from literals in the generator source.

## What it does

Flags a C# prefab generator (a file calling `PrefabUtility.`) that writes a `new Color(...)` or
`new Color32(...)` with numeric arguments, a named `Color.` value, an HTML color string or a
literal `fontSize`. Files marked generated are exempt.

## Why it matters

A literal in the generator forks the design from `crunk.toml`: the prefab drifts the next time a
token changes, and nothing notices.

## Remedy

Export the tokens with `crunk export csharp` and use the generated constants.

## Examples

### A Color literal fires

```csharp expect=fire file=Editor/HudPrefabBuilder.cs
class HudPrefabBuilder {
  void Build() {
    img.color = new Color(0.1f, 0.2f, 0.3f, 1f); // error: GX014 "generated token constant"
    PrefabUtility.SaveAsPrefabAsset(go, "Hud.prefab");
  }
}
```

### A token constant is clean

```csharp expect=clean file=Editor/HudPrefabBuilder.cs
class HudPrefabBuilder {
  void Build() {
    img.color = Tokens.ColorSurface;
    PrefabUtility.SaveAsPrefabAsset(go, "Hud.prefab");
  }
}
```
