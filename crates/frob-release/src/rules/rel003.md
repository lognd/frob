# REL003 changelog-fragment-required

A changelog fragment that is missing for the checked ticket or that fails validation.

## What it does

A fragment is `changelog.d/<ULID>.<type>.md` with a type of added, changed,
fixed, removed, deprecated or security, a ULID that names a ticket in the ledger,
and a non-empty ASCII body of one or two user-facing sentences. Repository-wide
the rule fires for each fragment that does not validate. Under `check --ticket`
it also fires when the checked ticket is not yet done and has no fragment file.
It is not applicable when `changelog_fragment` is not in `[pm] done_requires` and
the repository has no `changelog.d` directory. The per-ticket check skips a ticket whose
type is in `[pm] changelog_exempt_types` (default `epic` and `docs`) when it has no fragment;
a fragment such a ticket does carry is still validated.

## Why it matters

A bad fragment breaks `frob release changelog`; seeing it early keeps the release path clear.

## Remedy

For a missing fragment run `frob ticket fragment TICKET` in the ticket's
worktree, edit the sentence and commit it; or, audited, close the ticket with
`--no-changelog --reason TEXT`. For an invalid fragment fix what the message
names or replace it with `frob ticket fragment TICKET --force`.

## Examples

### A violating case fires

```rust expect=fire file=src/lib.rs
pub fn placeholder() {}
```

### A conforming case is clean

```rust expect=clean file=src/lib.rs
pub fn placeholder() {}
```
