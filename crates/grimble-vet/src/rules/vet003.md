# VET003 unvetted-transitive

A new transitive dependency that is not on the vet allowlist.

## What it does

Fires for a package that is new relative to the base lockfile, reached only through other dependencies, and not on the allowlist. It needs a base ref, so it is not applicable to a run without `--base`.

## Why it matters

Transitive crates are pulled in silently by a direct one; naming them keeps the dependency growth visible.

## Remedy

Review the crate and add it to `grimble-vet.toml` (the legacy `.grimble/vet.toml` is still read), or pick a direct dependency with a smaller tree.

## Examples

### Fire case 1

```toml expect=fire file=Cargo.lock config="base allow=a"
version = 4

[[package]]
name = "app"
version = "0.1.0"
dependencies = ["a"]

[[package]]
name = "a"
version = "1.0.0"
source = "registry+https://github.com/rust-lang/crates.io-index"
dependencies = ["b"]

[[package]]
name = "b"
version = "1.0.0"
source = "registry+https://github.com/rust-lang/crates.io-index"
```
