# VET001 unvetted-direct

A new direct dependency that is not on the vet allowlist.

## What it does

Fires for a package that is a direct dependency of a workspace member, is new relative to the base lockfile, comes from a registry or git source and is neither named nor pinned in `grimble-vet.toml` (the legacy `.grimble/vet.toml` is still read). It needs a base ref, so it is not applicable to a run without `--base`.

## Why it matters

A new direct dependency is code you now ship and trust; unvetted ones are how a typosquat or a hijacked crate gets in.

## Remedy

Review the crate, then add its name (`allow = ["serde"]`) or a pin (`"serde@1.0.200"`) to `grimble-vet.toml` (the legacy `.grimble/vet.toml` is still read).

## Examples

### Fire case 1

```toml expect=fire file=Cargo.lock config="base"
version = 4

[[package]]
name = "app"
version = "0.1.0"
dependencies = ["newcrate"]

[[package]]
name = "newcrate"
version = "1.0.0"
source = "registry+https://github.com/rust-lang/crates.io-index"
```

### Clean case 2

```toml expect=clean file=Cargo.lock config="base allow=newcrate"
version = 4

[[package]]
name = "app"
version = "0.1.0"
dependencies = ["newcrate"]

[[package]]
name = "newcrate"
version = "1.0.0"
source = "registry+https://github.com/rust-lang/crates.io-index"
```

### Clean case 3

```toml expect=clean file=Cargo.lock config="base"
version = 4

[[package]]
name = "app"
version = "0.1.0"
dependencies = []
```

### Clean case 4

```toml expect=clean file=Cargo.lock
version = 4

[[package]]
name = "app"
version = "0.1.0"
dependencies = ["newcrate"]

[[package]]
name = "newcrate"
```
