# CI007 no-event-interpolation-in-run

A `run:` script interpolates an expression an attacker can influence.

## What it does

Bound to zizmor `template-injection`.

## Why it matters

Unpinned or over-privileged workflows are a supply-chain and token-exposure risk, so the finding is raised where the workflow is declared.

## Remedy

Pass the value through an `env:` variable and read it as a shell variable instead of splicing `${{ ... }}` into the script. Raised by a `[[check.tool]]` stage with `parser = "zizmor-json-v1"`. Declared here until the grimble-ci crate owns the CI family; the id and meaning stay.

## Examples

### Fires case 1

```yaml expect=fire file=.github/workflows/ci.yml
on: issues
jobs:
  b:
    runs-on: ubuntu-latest
    steps:
      - run: echo ${{ github.event.issue.title }}
```

### Clean case 1

```yaml expect=clean file=.github/workflows/ci.yml
on: issues
jobs:
  b:
    runs-on: ubuntu-latest
    steps:
      - run: echo "$TITLE"
        env:
          TITLE: ${{ github.event.issue.title }}
```
