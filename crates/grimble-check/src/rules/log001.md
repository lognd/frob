# LOG001 direct-output

Direct output (print, println!, console.*, Console.Write*, sys.stdout and the like) outside the logging layer.

## What it does

Fires for a call or reference that writes to stdout, stderr or a file without going through the logging layer, in Rust, Python, JavaScript, TypeScript and C# files. The output atoms (language, symbol path, reason) are data in `docs/design/output-atoms.md`; the rule reads that catalogue, so adding an atom needs no code change. Detection is symbolic: imports, aliases and re-exports are resolved (`import sys as s`, `from sys import stdout as o`, `p = print`, `getattr(sys, "stdout")`, `builtins.print`, a wrapper re-exported from another file), so a local variable named `print`, a string or a comment is never a hit. Files matching `[log] modules` (the logging module itself), `[log] exempt` and test files are not judged. A dynamic target the scan cannot resolve (for example `console[name]`) is reported Unresolved.

## Why it matters

Output that bypasses the logging layer cannot be filtered, redirected, structured or silenced, and is lost when the process has no terminal.

## Remedy

Route the output through the configured logging crate. Agents must obey and not waive the finding. A human who intends the direct output waives it with `frob:waive LOG001 <reason>`; the reason is required.

## Examples

### Fires case 1

```python expect=fire file=app.py
import sys as s

s.stdout.write("hello")
```

### Fires case 2

```python expect=fire file=app.py
print("hello")
```

### Clean case 3

```python expect=clean file=app.py
def f(print):
    return print("x")


note = "print('hello')"  # print("hello")
```
