# COH003 mixed-abstraction-levels

A unit whose callees sit on abstraction layers further apart than the allowed spread.

## What it does

Fires for a function that calls both a high-level and a low-level helper: the layers of its callees differ by more than `max_level_spread` (default 1) of the `[coh]` table in `grimble.toml`. Built-in operators (slicing, indexing) and std string/slice methods (`find`, `trim`, `strip`) are layer-neutral and never count toward the spread. The layer of a callee comes from one of two sources, tried in this order and never mixed. First the grimble model: a `node` declaring `attr layer = N;` and `owns SEL;` puts every function defined in a file the selector surely matches on layer `N`. Second, when the model declares no layer at all, the module depth: a function defined in a deeper directory is a lower-level helper, and when every file sits at one depth the depth places nothing. A callee the layers cannot place (a library call sharing a repo name, a function in a file no layer source places) cannot prove a spread, so it never fails or warns; the names are logged at debug level. Method calls on a receiver other than `self`/`this` are layer-neutral too, since the method may belong to a library type. A callee name defined in several files is placed only when every definition agrees.

## Why it matters

A function that mixes steps of very different abstraction levels is hard to read: the reader switches between the business intent and the byte-level detail in one body.

## Remedy

Extract the low-level steps into a helper on the matching layer, so the function reads at one level.

## Examples

### Fires case 1

```python expect=fire file=top.py
def f(order, raw):
    total = price_order(order)
    head = helper()
    return total, head
```

```python file=price.py
def price_order(order):
    return order
```

```python file=a/b/helper.py
def helper():
    return 1
```

def f(order, raw):
