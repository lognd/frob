# COH002 decision-with-effects

A unit that branches on computed data and performs effects inside those branches.

## What it does

Fires in Rust, Python and TypeScript for a function whose `if`, `elif` or `match` condition is computed (it contains a call, or reads a variable the body itself defined) and whose branches call something in the effect vocabulary (`send`, `write`, `save`, `commit`, ...). A guard on a bare parameter is a dispatch guard, not a decision. Logging, metrics and asserts are trivial and never count as an effect. A branch that calls something outside both vocabularies leaves the verdict Unresolved, naming those callees, rather than passing silently. The vocabularies are the `effect_calls` and `trivial` lists of the `[coh]` table in `grimble.toml`; a configured list replaces the built-in one.

## Why it matters

A function that decides and acts in the same body mixes the functional core with the imperative shell, so the decision cannot be tested without performing the effect.

## Remedy

Return the decision from a pure function and perform the effect in the caller, or mark a deliberate shell with `grimble:shell`.

## Examples

### Fires case 1

```python expect=fire file=app/relay.py
def f(a, sink):
    x = compute(a)
    if x > 3:
        sink.send(x)
    return x
```

### Fires case 2

```rust expect=fire file=src/lib.rs
pub fn f(a: u32, sink: &Sink) -> u32 {
    let x = compute(a);
    if x > 3 {
        sink.send(x);
    }
    x
}
```

### Clean case 3

```python expect=clean file=app/relay.py
def f(a, sink):
    if a > 3:
        sink.send(a)
    x = compute(a)
    if x > 3:
        log(x)
    return x
```

### Unresolved case 4

```python expect=unresolved file=app/relay.py
def f(a, sink):
    x = compute(a)
    if x > 3:
        mystery(x)
    return x
```
