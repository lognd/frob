# COH001 independent-jobs

A unit that does two or more independent jobs.

## What it does

Fires in Rust, Python and TypeScript for a function whose top-level statements fall into two or more components that share no data. The statements are connected over the def-use edges, once with every edge (May edges included) and once with Must edges only: the rule fires when two components remain even with every May edge joined, is clean when the Must-only count is one or fewer, and is Unresolved otherwise, naming the May edges (an aliased write, a call that may mutate its argument) that decide it. Parameters glue nothing, a returned value is an output that joins no component, and logging, metrics and asserts are removed before counting. A component of fewer top-level statements than `min_slice_statements` of the `[coh]` table in `grimble.toml` (default 2) is not a job; the `trivial` list of the same table adds callee names to the built-in logging vocabulary.

## Why it matters

A function that does two unrelated things under one name cannot be read, tested or reused as either of them.

## Remedy

Extract each job into its own unit and call both from the original.

## Examples

### Fires case 1

```python expect=fire file=app/jobs.py
def f(a, b):
    x = a + 1
    y = x * 2
    z = b - 1
    w = z * 3
    return y, w
```

### Clean case 2

```python expect=clean file=app/jobs.py
def f(a, b):
    x = a + 1
    y = x * b
    z = y - a
    return z
```

### Unresolved case 3

```python expect=unresolved file=app/jobs.py
def f(a, b, p, q):
    t = a + 1
    p.v = t * 2
    u = b + 1
    y = q.v + u
    return y
```
