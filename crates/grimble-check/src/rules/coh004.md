# COH004 mixed-vocabularies

A unit whose identifiers fall into two or more disjoint vocabularies.

## What it does

Fires in Rust, Python and TypeScript for a function whose identifiers, split into words on `_` and camelCase boundaries, form two or more clusters that no top-level statement links. Words shorter than three characters and generic words (`self`, `get`, `result`, `value`, ...) are dropped, and a cluster needs at least two distinct words to count as a vocabulary. The rule is a heuristic, so it never fails a run: the severity model has no Advisory (rules.md 6.1.1), and the finding is reported Unresolved, naming the clusters.

## Why it matters

A function that talks about invoices in one half and packet buffers in the other usually serves two audiences, so neither reader finds it where they look.

## Remedy

Split the function along the vocabularies, one unit per domain.

## Examples

### Unresolved case 1

```python expect=unresolved file=app/mixed.py
def f(order, sock):
    total = order.line_total + order.sales_tax
    invoice = order.invoice_total(total)
    packet = sock.read_packet_buffer()
    sock.send_packet_header(packet)
    return invoice
```

### Clean case 2

```python expect=clean file=app/one.py
def f(order):
    total = order.line_total + order.sales_tax
    invoice = order.invoice_total(total)
    order.line_total = invoice
    return invoice
```
