# SYS012 sys-excuse-grant

A template excuse overlaps a may grant.

## What it does

Fires per (excuse, grant) pair when a `template` entity says `excuse ATOM for SEL because="..."` and a node holds `may ATOM'` where `ATOM'` equals `ATOM`, is an ancestor of it (`fs` for `fs.read`) or a descendant, and `SEL` selects a file the grant covers (its `at` selection, or the files the node owns). Only the model is read: no code is inspected, so the finding is always Exact and never Unresolved (binding.md 6.12).

## Why it matters

The excuse says the atom does not apply to that code and the grant says the node may use it. Both cannot hold, and the excuse's reason would hide a real grant.

## Remedy

Delete the excuse, narrow its selector away from the granted code, or remove the grant.

## Examples

### Fires case 1

```grmb expect=fire file=design/m.grmb config="py"
grimble = "2";
module m;

template gen {
  excuse net for "src/x.py" because="generated stubs never touch the network";
}
node a : trusted {
  owns "src/x.py";
  may fs.read;
  may exec;
  may net.listen;
}
node d : trusted {
  owns "design/**";
}
```

### Clean case 2

```grmb expect=clean file=design/m.grmb config="py"
grimble = "2";
module m;

template gen {
  excuse net for "src/other/**" because="generated stubs never touch the network";
}
node a : trusted {
  owns "src/x.py";
  may fs.read;
  may exec;
  may net.listen;
}
node d : trusted {
  owns "design/**";
}
```
