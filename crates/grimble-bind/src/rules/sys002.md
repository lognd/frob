# SYS002 sys-ambiguous-owner

Two nodes own one identity at the same specificity.

## What it does

Fires when two Must rows of the owns selectors tie at the maximal specificity vector and no directive names one of the tied nodes; the owner is Unknown. A tie that includes a May row is Unresolved: it may not be a tie. A tie is never broken by file order or name.

## Why it matters

When two nodes own one thing at equal specificity, the owner is unknown and every rule that asks "whose is this" has no answer.

## Remedy

Make one `owns` more specific, or remove the overlap. A tie is never broken by order.

## Examples

### Fires case 1

```grmb expect=fire file=design/m.grmb
grimble = "2";
module m;

node a : trusted {
  owns "src/**";
}
node b : trusted {
  owns "src/**";
}
node d : trusted {
  owns "design/**";
}
```

### Clean case 2

```grmb expect=clean file=design/m.grmb
grimble = "2";
module m;

node a : trusted {
  owns "src/**";
}
node d : trusted {
  owns "design/**";
}
```
