# CAP001 cap-undeclared

Code a node owns uses a capability atom the node does not grant.

## What it does

Deny by default (binding.md 7.2 item 3): fires once per node and atom when a call in Must-owned code matches the callee vocabulary of the atom for its language and no `may` of the node covers it (the atom itself or its parent, at the grant's `at` files). One finding per node and atom, anchored at the node, so an `accept CAP001` inside the node suppresses it. Unresolved when the code is owned only at May. An excuse never hides a use (CAP004 is not implemented yet).

## Why it matters

A capability the model does not grant is one no review of the model ever saw, so the node can do more than it declares.

## Remedy

Grant the atom with `may` on the node, or remove the use.

## Examples

### Fires case 1

```grmb expect=fire file=design/m.grmb config="py"
grimble = "2";
module m;

node a : trusted {
  owns "src/x.py";
}
node d : trusted {
  owns "design/**";
}
```

### Clean case 2

```grmb expect=clean file=design/m.grmb config="py"
grimble = "2";
module m;

node a : trusted {
  owns "src/x.py";
  may fs.read;
  may exec;
  may net.listen;
}
node d : trusted {
  owns "design/**";
}
```
