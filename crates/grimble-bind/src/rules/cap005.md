# CAP005 cap-grant-unacknowledged

A new or widened `may` grant has no human acknowledgement.

## What it does

Fires per `may` clause that `grimble.grants.toml` does not cover: no approval names the node, atom and arguments (a new grant), or the grant matches a file its approved selectors do not (a broader `at`, or a node whose `owns` grew under a whole-node grant). It stays quiet when the repository keeps no `grimble.grants.toml`. An approval is recorded by `grimble ack --grants --reason "..."`, which refuses an agent (E-ATTEST-NOT-HUMAN) and anyone not in frob.toml `[evidence] attesters` (E-ATTEST-NOT-ATTESTER). Narrowing or removing a grant needs no ack.

## Why it matters

A `may` clause is the permission a node grants itself; if a model edit can add one and pass, review of the model never has to see it.

## Remedy

Have an attester run `grimble ack --grants --reason "why"` and commit the ledger, or revert the grant.

## Examples

### Fires case 1

```grmb expect=fire file=design/m.grmb config="grants"
grimble = "2";
module m;

node a : trusted {
  owns "src/**";
  may fs.read at "src/**";
}
node d : trusted {
  owns "design/**";
}
```

### Clean case 2

```grmb expect=clean file=design/m.grmb config="grants"
grimble = "2";
module m;

node a : trusted {
  owns "src/**";
  may fs.read at "src/lib.rs";
}
node d : trusted {
  owns "design/**";
}
```
