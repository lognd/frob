# SYS004 sys-entity-without-code

A binding clause matches no code.

## What it does

Fires per owns, shape or evidence clause (and once per flow whose ends are both empty) when the clause's selector matches no unit and hides none. Suppressed when the selector's path matches no file (MDL005 says so). Unresolved when only May rows or hidden placeholders are found.

## Why it matters

An entity whose selectors match no code describes nothing that exists, so the checks over it are vacuous.

## Remedy

Correct the selector, or remove the entity until the code lands.

## Examples

### Fires case 1

```grmb expect=fire file=design/m.grmb
grimble = "2";
module m;

node a : trusted {
  owns "src/lib.rs";
  owns "src/lib.rs::nothing";
}
node d : trusted {
  owns "a/**";
  owns "b/**";
  owns "tests/**";
  owns "docs/**";
  owns "design/**";
  owns "src/loose.rs";
}
```

### Clean case 2

```grmb expect=clean file=design/m.grmb
grimble = "2";
module m;

node a : trusted {
  owns "src/lib.rs::run";
}
node d : trusted {
  owns "a/**";
  owns "b/**";
  owns "tests/**";
  owns "docs/**";
  owns "design/**";
  owns "src/loose.rs";
}
```
