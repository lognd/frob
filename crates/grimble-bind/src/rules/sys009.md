# SYS009 sys-flow-end-unbound

One end of a flow binds no code while the other does.

## What it does

Fires when a flow's producer or consumer end has no row at all, the endpoint node owns code and the other end is not empty too (then it is SYS004). Unresolved when the end holds only May rows or hidden placeholders, or asked for pack inference that cannot run yet.

## Why it matters

A flow with one end bound to code is half a contract: the other end could be anything.

## Remedy

Bind the missing end with `producer` or `consumer`, or correct the symbol the message names.

## Examples

### Fires case 1

```grmb expect=fire file=design/m.grmb
grimble = "2";
module m;

node a : trusted {
  owns "a/**";
}
node b : trusted {
  owns "b/**";
}
node d : trusted {
  owns "src/**";
  owns "tests/**";
  owns "docs/**";
  owns "design/**";
}
flow half : a -> b {
  producer "a/lib.rs::send";
  consumer "b/lib.rs::absent";
}
```

### Clean case 2

```grmb expect=clean file=design/m.grmb
grimble = "2";
module m;

node a : trusted {
  owns "a/**";
}
node b : trusted {
  owns "b/**";
}
node d : trusted {
  owns "src/**";
  owns "tests/**";
  owns "docs/**";
  owns "design/**";
}
flow whole : a -> b {
  producer "a/lib.rs::send";
  consumer "b/lib.rs::recv";
}
```
