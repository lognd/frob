# SYS001 sys-unowned

An artifact in the walk that no node owns.

## What it does

Fires when no unit of the artifact has an owner and the artifact hides nothing a selector could claim; reported once per directory. Unresolved when an owner is May only, the artifact has an unseen remainder, or only a symbol selector could own an F0 file. An artifact under a `modeled` selector is SYS005's. Error under `[grimble] strict`.

## Why it matters

Code that no node owns is outside the model, so no flow, claim or capability check sees it.

## Remedy

Add the path to the `owns` of the node it belongs to, or declare a node for it.

## Examples

### Fires case 1

```grmb expect=fire file=design/m.grmb
grimble = "2";
module m;

node a : trusted {
  owns "src/**";
}
node d : trusted {
  owns "design/**";
}
```

### Clean case 2

```grmb expect=clean file=design/m.grmb
grimble = "2";
module m;

node all : trusted {
  owns "src/**";
  owns "a/**";
  owns "b/**";
  owns "tests/**";
  owns "docs/**";
  owns "design/**";
}
```
