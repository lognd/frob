# SYS011 sys-vmodel-link-broken

A vmodel ref or runnable resolves to nothing.

## What it does

Fires when a `ref` or `runnable` of a vmodel matches no unit although its target file is in the walk; a runnable that selects no test unit fires too. The message ends with `nearest real id: ...` when the file holds a close id. A `manual` test has no runnable and is never judged. Several matches are SYS003 ambiguous-singleton. Unresolved when the target hides units or the match is May only.

## Why it matters

A V-model link points at a document section or test. If the section or test is gone, the link verifies nothing.

## Remedy

Fix the `ref` or `runnable` so it names something that exists, and that is a test.

## Examples

### Fires case 1

```grmb expect=fire file=design/m.grmb
grimble = "2";
module m;

node a : trusted {
  owns "src/**";
  owns "a/**";
  owns "b/**";
}
node d : trusted {
  owns "design/**";
  owns "docs/**";
  owns "tests/**";
}
vmodel t_bad {
  kind test;
  level customer_test;
  runnable "tests/t.rs::absent";
}
```

### Clean case 2

```grmb expect=clean file=design/m.grmb
grimble = "2";
module m;

node a : trusted {
  owns "src/**";
  owns "a/**";
  owns "b/**";
}
node d : trusted {
  owns "design/**";
  owns "docs/**";
  owns "tests/**";
}
vmodel t_ok {
  kind test;
  level customer_test;
  runnable "tests/t.rs::it_works";
}
```
