# CAP002 cap-declared-unused

A node grants a capability atom that no code it owns uses.

## What it does

Fires per `may` clause when every file the node owns is fully seen, every language present has a detector for the atom and no use is observed in the grant's scope (binding.md 7.2 item 6). Silent, never clean, when a language has no detector, the code is owned only at May or a file hides units: absence is then not Exact.

## Why it matters

A grant nothing uses widens what the node is allowed to do for no reason.

## Remedy

Remove the `may` clause, or keep it with an `accept CAP002` and a reason.

## Examples

### Fires case 1

```grmb expect=fire file=design/m.grmb config="py"
grimble = "2";
module m;

node a : trusted {
  owns "src/x.py";
  may fs.read;
  may exec;
  may net.listen;
  may net.connect;
}
node d : trusted {
  owns "design/**";
}
```

### Clean case 2

```grmb expect=clean file=design/m.grmb config="py"
grimble = "2";
module m;

node a : trusted {
  owns "src/x.py";
  may fs.read;
  may exec;
  may net.listen;
}
node d : trusted {
  owns "design/**";
}
```
