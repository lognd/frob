T-5289: fix_test010_redundant_test_declaration applied each finding's fix using the pre-fix snapshot's line number, so a second finding in the same file was applied against a file already shrunk/grown by an earlier finding, deleting or inserting at the wrong physical line and corrupting real source (observed corrupting src/frob/check/_python.py during a land, breaking every land since). Every DELETE/MOVE finding is now planned against the original snapshot's line numbers first, then all edits for one file are applied in a single batched pass sorted by descending original line number, so an earlier edit in a file can never invalidate a later finding's recorded line. Writes that would leave a .py file unparseable are refused rather than applied, as a last-resort guard against any future variant of this bug.
