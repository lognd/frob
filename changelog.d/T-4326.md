T-4326: DECISION: the defect is in the HELPER, not (only) the test. `_resolve_win32_executable` gated its "already a path" check on `os.sep`/`os.altsep`, which reflect the REAL host OS the interpreter is compiled for, not the win32 target this function is checking for via `sys.platform`. On a real Windows host this coincidentally works (`os.sep == "\\"`, `os.altsep == "/"`), so it is invisible in production, but it made the win32 branch untestable off real Windows for backslash-style paths: `test_noop_for_a_path_like_name_on_win32` fakes `sys.platform == "win32"` while running on posix, where `os.sep == "/"` and `os.altsep is None`, so `"C:\\tools\\gh.exe"` slipped past the separator check and fell through to a genuine `shutil.which()` call. On Python 3.12+, `shutil.which` itself gates a `_winapi.NeedCurrentDirectoryForExePath` call behind its own `sys.platform == "win32"` check -- and since `monkeypatch.setattr ("frob.gitio.sys.platform", ...)` patches the one process-global `sys` module, `shutil`'s internal check saw "win32" too and crashed with `AttributeError: 'NoneType' object has no attribute 'NeedCurrentDirectoryForExePath'` (`_winapi` is `None` off Windows) -- exactly CI's reported failure. Reproduced standalone on Python 3.13 (`_resolve_win32_executable`'s pre-fix logic raises that exact AttributeError; the fixed logic returns cleanly) and via `shutil.which`'s own stdlib source (`_win_path_needs_curdir` calls `_winapi.NeedCurrentDirectoryForExePath` whenever `sys.platform == "win32"`). FIX: `src/frob/gitio.py::_resolve_win32_executable` now checks for the literal separators `"\\"` and `"/"` (Windows' own two, which it always accepts regardless of what `os.sep` names on the compiling host) instead of `os.sep`/`os.altsep`. This is correct for every real Windows host (same behavior as before there) and makes the win32 no-op branch exercisable -- and correctly no-op -- from a test running on any platform, closing the gap the sibling tests already worked around by stubbing `shutil.which` directly. `import os` removed from `gitio.py` (no longer used anywhere in the module). `tests/test_gitio.py::TestResolveWin32Executable .test_noop_for_a_path_like_name_on_win32` additionally now stubs `shutil.which` to raise if ever called, as defense-in-depth documentation of the no-op contract (matching its siblings' existing pattern), and its docstring records the T-4326 root cause for the next person who touches this test group.
