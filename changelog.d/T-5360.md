T-5360: COMPLY rules need to know two things before they can fire usefully: does this repo's manifest imply a compliance-relevant behavior (billing, SMS, AI on user data, a session-replay/pixel script, health data, ...), and does the repo actually publish the privacy/terms/accessibility pages that behavior implies it should. This ticket adds both as a pure file-presence/content-sniff substrate, matching T-5302's detect_frameworks shape exactly and depending on it for framework detection rather than re-implementing it. Required-page detection is keyed off the already- detected FrameworkKind set and returns a typani Result so a genuinely unreadable root (not just "nothing detected") is distinguishable from an honest empty answer. Fixtures give one positive-control repo per signal plus a plain negative control, and present/missing pairs per router style (file-based Next.js, config-based Flask) for required-page detection.
