WHY --- This is the real root cause behind the T-3259 incident I found and documented (but could not fix in-scope) while working T-4659: T-4659's own scope was `src/frob/tickets/_leases.py` only, and the actual bug lives in `frob.tickets._evidence._sync_cross_worktree_lease`, which reads `ticket.state` from the CALLING checkout's own local view before the transition. Because `tickets.md` is per-branch (T-0473's entire premise), a ticket started `IN_PROGRESS` in worktree A, never merged back to `main`, has a lease file `main`'s own ledger never saw created. Dropping/ closing/requeuing that ticket FROM `main` computed `from_state` as whatever `main`'s stale local view said (`PLANNED` in the reproduced case) -- never `IN_PROGRESS` -- so the release branch never fired and the lease file survived. This is EXACTLY the observed T-3259 shape: a coordinator dropping a ticket from the primary checkout that was worked in a dispatched agent worktree. Fix: stop asking "did the LOCAL view see IN_PROGRESS a moment ago" and instead always attempt the release whenever the ticket is not entering IN_PROGRESS. `release_lease` was already written to be a safe idempotent no-op on a missing file, so this has zero cost/behavior change for the overwhelming common case (no lease held) and closes the gap for the cross-worktree case.
