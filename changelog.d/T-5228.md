A worker wedged in native/blocking code (a PyO3 extension call, a held OS lock, a blocking syscall) never crashes and never yields to pytest-timeout's own thread-method watcher either, so neither mechanism ever fires -- the run's only remaining backstop was the external, job-level 2400s SIGABRT, which prints no test name at all (both observed macOS incidents in runs 35510697497 and 35654510898 hang with zero SUITE-RESULT-FAILED lines before the abort). Fix: a second, independent, crash-free stall predicate (`_stall_detected_no_crash`) checked every watchdog poll, with its own env-overridable threshold (`FROB_XDIST_STALL_ABORT_SECONDS_NO_CRASH`, default 1500s -- comfortably under the 2400s job ceiling). It reuses the existing `_format_stalled_item_lines` marker mechanism (`_announce_stall_and_abort`, now `no_crash`-aware) to name the actual in-flight test nodeid via the same T-3516 marker files, then hard-exits via os._exit -- same shape as the crash-gated path, just without requiring a crash first. Measured: tests/unit/test_conftest_stackdump.py (40 tests, including the new test_stall_detected_no_crash_fires_without_a_crash) passes clean.
