T-5259: drain_next's per-entry _LandReportShim only carried commit_sha/final_id, but _print_land_proof reads report.ticket_id for its claims/orphan-evidence/ budget-deferred lookups (T-2091/T-2275/T-2456), so it raised AttributeError right after the first entry landed. That AttributeError propagated out of drain_next, so `frob ticket land --drain` silently stopped after one landed ticket per invocation instead of draining the whole queue (observed in /tmp/land-T-5035.log and /tmp/land-T-4560.log). The fix sets self.ticket_id = final_id in _LandReportShim.__init__, mirroring what a real LandReport already provides -- on a drained queue entry final_id and ticket_id are always the same value (the entry's ticket id), so this is a one-line completion of the existing shim, not new behavior. Regression test constructs a bare _LandReportShim and runs it through _print_land_proof (with _land_proof_checks stubbed to avoid real git/ledger plumbing), asserting no AttributeError and a clean verified=True return.
