T-5393: Newer ruff (0.15.16+) prints "Would reformat: <path>" with a trailing colon, but the two parsers of this line (frob.gates._land_format and frob.check._python) only stripped the older colon-less "Would reformat " prefix, leaving "Would reformat: <path>" used verbatim as a filename -- breaking the pre-land rewrite (ENOENT on hundreds of bogus paths) and voiding waiver/scope path-shape identity in frob check's Diagnostic.file. Extracted one shared parser, frob.process.parsers.ruff. parse_ruff_would_reformat_paths, anchored on the regex "^Would reformat:? (.+)$" so both ruff versions resolve to the same real path; both call sites now use it, with a positive control for both line shapes and a regression test that the land-format rewrite path only ever receives paths that exist on disk. docs/modules/gates.md's LANDFMT001 section documents the shared parser and the bug it fixes.
