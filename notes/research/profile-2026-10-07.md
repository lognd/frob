# frob v2 command profile, 2026-10-07/08

Scope: every leaf command of the frob, grimble and crunk binaries, run against a local clone of the
frob-v2 repository. Analysis only: no source change, no ticket, no commit. The primary checkout was
only read (one `git count-objects`, one `git status`, and executing its prebuilt `target/debug/frob`
against the clone).

Headline: the repo's 1406-ticket ledger is read through a git path that re-decodes the whole tickets tree
for every file (gob-git `read_blob_at`), and the ticket index is thrown away and rebuilt from scratch whenever
the tickets tree changes by anything other than an in-process ticket write. That one pair explains every
slow ledger verb, the "23 s" `ticket doable`, and most of the slow `cycle`/`milestone`/`release` writes. The
second family is uncached or duplicated symbol-graph work in `frob test`, `grimble ack`, and the three
products each re-walking and re-digesting 10.9k files. The third is `frob check` and `frob land`, where
external tools run serially and land runs the whole check pipeline three times with cold cargo target dirs.

## 1. Environment

- Machine: aarch64 Linux (WSL2 kernel 6.6.87.1-microsoft-standard-WSL2), 12 cores, 23 GiB RAM, ext4 on /dev/sdd,
  ~700 GB free at start. The host is SHARED: other agents run frob, cargo and rustc in parallel. Load
  average was 8-30 during most runs and peaked at 104 during the real `frob test` run. Absolute numbers
  below are therefore noisy (+-30%, ticket doctor swung 4.9 s to 9.0 s between two quiet-looking
  moments); relative findings are what to trust. Medians of 5 are given; mins are in `out/*.json`.
- Commit: 3c0c6a64bd89031715163b7cd9705705d5aea152 (branch experimental), local clone with origin
  re-pointed to a scratch bare repo so nothing could push to the primary.
- Toolchain: rustc 1.98.0 (88d9e12ae 2026-08-18); hyperfine 2.0.0 (installed with `cargo install` into
  ~/.cargo/bin, the only change outside the scratch dir); perf 5.15 binary from /usr/lib/linux-tools-5.15.0-198
  (the /usr/bin/perf wrapper does not match the WSL kernel), software event cpu-clock at 499 Hz.
- Build: `cargo build --release -j 6 -p frob-cli -p grimble -p crunk` (package for the `frob` binary is
  `frob-cli`). The root Cargo.toml defines no `[profile.release]`, so release = opt-level 3, no LTO by
  default, codegen-units 16. Overrides used: CARGO_PROFILE_RELEASE_LTO=false, _DEBUG=line-tables-only,
  _STRIP=none, _PANIC=unwind. A second build with `RUSTFLAGS=-C force-frame-pointers=yes` was used for
  `perf --call-graph fp` (DWARF unwinding of the 180 MB binary made perf report take > 4 min per
  profile; frame pointers made it 0.1 s).
- Method: hyperfine `-N --warmup 1 --runs 5` for read-only verbs (cwd = clone); "cold" = `rm -rf .frob
  .git/frob/cache` before each of 3 runs. Mutating verbs ran in a second clone (`mut`) with a prepare script
  per run: `git reset --hard` to the base commit, delete extra branches/tags/worktrees/leases, restore a warm
  `.frob/` (ticket index only), then optional setup (e.g. create cycle, take a lease); 5 runs, no warm-up.
  Max RSS is the max over `/usr/bin/time -f %M` of one extra run. `--timing` exists only on `frob check`
  (and grimble/crunk check); for other verbs I used `-vv` log timestamps and perf.
- Caches (docs/design/architecture.md section 2 and 3): `.frob/tickets.sqlite` (ticket index, keyed by the tickets
  subtree id + handle_min_len), `<git common dir>/frob/cache/<product>/cache.sqlite` (parse artifacts and
  findings), plus `.frob/cache.sqlite` opened separately by `frob ack` (frob-ack/src/inputs.rs). The engine
  fingerprint folds in the executable size+mtime ("exe:183778184-..." in `-vv`), so every new build of the
  binary is a cold cache; profile after a warm-up run of the same binary.
- Skipped (reason): none skipped for network. `frob ticket evidence add/fetch` and `milestone evidence add` ran
  with the `file` provider (no network). `frob release cut` ran without `--push`; `frob land` without `--push`;
  `frob ack` and `grimble ack` ran with `--reason`. `frob ticket triage ...` needed a triage-state ticket
  created in the prepare step. `frob test` (real) was run once: 1322 s, see section 3.
- Noise events I caused and corrected: the first RO pass overlapped my own exploratory writes (cold
  ticket verbs read 1-10 s); the whole RO set was re-run quietly and replaces them (section 2 uses the
  re-run; the first pass is kept in `run1/`).

## 3. Hot-spot analysis (slowest commands and everything over 1 s warm)

Percentages are perf samples (cpu-clock, frame-pointer unwinding, children included, after a warm-up
run so caches are warm unless noted). "crate/file:function" are source locations in the clone at
3c0c6a64b. Hypotheses are marked H; things I measured are not.

### 3.1 Known suspects: verdicts

1. `frob ticket doable` ~23 s (ticket ~ZZQ6PA9): NOT reproduced as a steady state with a release build.
   Warm 18-32 ms, cold (index rebuild) 0.43-0.62 s on 1406 tickets. It IS reproduced with the primary's
   debug binary: cold 6.3 s, warm 0.13 s, and the cold path is ~100% the full ledger re-read of section 3.2. Rebuilds
   are not rare: any change of the tickets subtree not made by an in-process ticket writer (a cycle or milestone
   write, a merge or pull that brings in other agents' ticket commits, `reset`) invalidates the index; I measured
   0.74 s for the `doable` after one `milestone new`, and 0.68 s for `ticket list` after one
   `milestone criterion add`. With opt-level 0 gix/zlib (x12), plus load average 30-100 from parallel agents, 23 s
   is the expected number. Verdict: confirmed as "full rebuild on every tree change, amplified by the dev profile",
   not as a property of `doable`.
2. gob-git resolving each blob path through the tickets tree (ticket ~VXFAY3P): CONFIRMED, the dominant cause.
   `Repo::read_blob_at` (crates/gob-git/src/read.rs:213) does `rev_parse(rev)` -> `tree_of` (find commit, peel to the
   root tree, read.rs:225) -> `Tree::lookup_entry_by_path`, then `find_blob`, for EVERY file. The root tree and the
   1406-entry `tickets/` tree are inflated again each time (they are mostly loose objects: gix `loose::Store::try_find`
   67-70% of samples, `zlib_rs::inflate_fast_help` 56-66% self). Even the "walk once" `read_events_many_at`
   (ledger.rs:555) reads each listed file through `Ledger::text` -> `read_blob_at(root_oid, path)`, so it still
   decodes the tickets tree per file. The ticket tree grows with every ticket, so the cost is O(files x tree entries).
3. `frob land` re-check ~7 min: REPRODUCED (451.8 s and 643.0 s), see 3.8. It is three whole `check` passes plus cold
   cargo builds in two fresh checkouts, not a single re-check.

### 3.2 Ledger read path (ticket doctor 4.9-9 s, cycle velocity 2.2 s, board 1.9 s, doctor 0.84 s, and every cold ticket verb)

Common stack (all five profiles): `Ledger::{doctor,events,events_many,read_all_tickets}` ->
`Ledger::text` (crates/frob-ledger/src/ledger.rs:361) -> `gob_git::Repo::read_blob_at` -> gix
`Tree::lookup_entry_by_path` / `Repository::find_object` -> `loose::Store::try_find` -> zlib inflate.

| command | warm | what dominates (perf) | source |
|---|---|---|---|
| `frob ticket doctor` | 4.9 s (9.0 s under load) | 78% `read_blob_at`; `Ledger::doctor` 59-62% of which `read_events_at` 50%; `home_path_findings` 37-40% (7386 files scanned); `list_files`/`diff_names` 11%; `rev_parse` 12%; toml parse 8% | frob-ledger/src/doctor.rs (`Ledger::doctor`), privacy.rs:180 (`home_path_findings`), ledger.rs:523 (`read_events_at`), ledger.rs:529 (`list_files` per ticket) |

| `frob board` | 1.9 s | 98% `board_cmd::read_events` -> `Ledger::events_many`; `Ledger::text` 89%; `tree_of` (commit -> root tree inflate) 67%; `rev_parse` 8% | frob/src/board_cmd.rs:69, ledger.rs:555 |

H (per-call cost): each call decodes a ~60 KB `tickets/` tree plus a commit and a root tree: roughly 7000 x
(2 loose-object inflates of 10-60 KB) = ~0.4 GB of zlib output for `ticket doctor`. Reading blobs by oid from one
recursive tree walk, or just turning on gix's object cache (`object_cache_size`), removes nearly all of it.
`rev_parse` of the same spec string 7000 times also costs 12-19% (gix prefix disambiguation under
`gix_revision::spec::parse`): resolve once.

### 3.3 Index invalidation (cycle plan --apply 7.4 s, cycle assign 1.26 s, unassign 0.97 s, milestone add 1.08 s, release cut 2.9 s, release bump 0.73 s)

perf of these shows the same stack under `Ledger::synced` -> `read_all_tickets` (85-94%), i.e. a complete re-read
of all tickets, not an incremental update:
- `cycle plan --apply` (frob/src/cycle_cmd.rs:967 `assign_one`, 90%) calls `member_points`
  (cycle_cmd.rs:882) which calls `Ledger::show` per member; `show` calls `synced()`, and after the previous
  member's commit the key (tickets subtree id) no longer matches, so each member costs one complete rebuild
  (O(members x tickets)): 7.4 s for the 1-2 member test cycle in the probe.
- `cycle assign/unassign`, `milestone add`, `release cut` and `release bump` (frob-release/src/cut.rs
  `commit_release`, `report_for`) all run after a pm write (cycle/milestone events live under the same tickets
  subtree) so the next `synced()` is a full rebuild. `Ledger::synced` (ledger.rs:666) compares the stored key to
  the current `tree|handle_min_len` key and on any difference rebuilds everything; only `commit_events` updates the
  key incrementally ("index updated incrementally" in -vv).
- Cheap pm verbs that do not touch the index (`cycle new` 0.12 s, `cycle close` 0.14 s, `milestone new` 0.06 s,
  `criterion add/remove` 0.05-0.06 s, `evidence add` 0.05 s) show the baseline for a pm write.

### 3.4 `frob test` 5.6-7.2 s without running tests; `frob ack`, `frob graph why/affects`

- `frob test --dry-run --base HEAD~30` / `--base HEAD~1` (5.8-7.2 s, 18-22 CPU-s, 456 MB): crates/frob-tests/src/touched.rs:64
  `build_graph(root, &walked.files, &Cache::null())`. The cache is explicitly null, so every run parses all
  ~3000 source files: 75-81% in `gob_symbols::pipeline::extract_file` -> `fold_file` (rayon), `ts_parser_parse` 49-52%,
  `RustAdapter::fold` 49%. Inside it, `Fold::macro_call` -> `Fold::rest_group` -> `Fold::scan_macro`
  (crates/gob-symbols/src/rust.rs:1838) is 35-43% of ALL samples: macro bodies are re-lexed by a second
  tree-sitter parse (`ts_lex` 18% self, `ts_lexer__advance` 10%). Cold == warm for this verb, which is itself the finding.
- `frob test --base ... ` real: 14 s of frob work, then `cargo nextest` for 1208 s (1396 tests, debug build from
  an empty target under heavy host load); frob's share is the graph above.
- `frob ack <file>` / `ack --dry-run --all` / `graph why|affects` (0.9-1.6 s warm, ~410 MB, cold 4-7 s): three roughly
  equal slices on the warm path: `WorktreeReader::read` 32-34% (gix `filter::Pipeline::convert_to_git` 17%,
  `Repository::open_index` 15%, sha1 7%+4%, `eol::Stats::from_bytes` 4%), `SymbolGraph::link_calls` ->
  `resolve_site` 23-26% (crates/gob-symbols/src/graph.rs:2041 and :1339; not cached, derived every run) and
  `build_graph_with_stats` 17% (cache hits: decode postcard per file + SipHash 5-8% self).
  `frob ack` opens its OWN cache, `Cache::open(root/.frob)` (crates/frob-ack/src/inputs.rs:147, also
  frob-ack/src/rules.rs:453), instead of the repository-shared sqlite that `check` uses, so a `check` never
  warms an `ack`, and a fresh worktree starts cold (the 4.4 s `ack.real` row).

### 3.5 `grimble ack` 5.7-9 s, 1.35 GB RSS (and the cold paths of grimble check / exceptions list)

`Ack::run` -> `grimble_check::bind_repo` (grimble-check/src/lib.rs:245) -> `grimble_bind::bind` -> `Code::build`
(crates/grimble-bind/src/code.rs:102, rayon over every file) -> `gob_symbols::fold_file`
(code.rs:143): 53% of samples, with no cache argument at all; `ts_parser_parse` 37-39%,
`Fold::scan_macro` 25%, `gob_ir::term::Term::units` 16% self (a hot linear walk), `gob_ir::select::unseen`
3%. Memory: the whole U-term of the repo is held at once (1.35 GB). The verb then fails: `--dry-run --all`
exits 2 E-ACK-EMPTY and `grimble ack design/model.grmb --reason ...` exits 3 E-ACK-REFUSED, both only
after this full bind. Argument/precondition validation that needs no binding (a reason given, something named,
file has a `Must` binding) could run first.
`grimble check`/`exceptions list`/`crunk check`: warm 0.3-0.6 s but 65% of the warm profile is
`ContentReader::read` per file (the same per-chunk reader as 3.4: `gix::Repository::filter_pipeline` 24% and
`open_index` 23% are paid once per rayon chunk because `WorktreeSource::with_reader`
(crates/gob-git/src/content.rs:144) opens a fresh repository per use); cold is 5.7-7.6 s from the parse.

### 3.6 `frob check` warm 6.8-11 s, cold 33-53 s

Warm stages (`--timing`): walk 286 ms, graph 623 ms, directives 35, file-rules 299 = 1.3 s budgeted, and
`tools_ms` 5991: `cargo fmt --check` 1629, clippy 713 and `cargo dev gen all --check` 507, zizmor 256, actionlint 434,
cargo-deny 1191, cargo-shear 437, typos 94, grimble sibling 730. They run one after another
(`gob_check::tools::run_tools`, crates/gob-check/src/tools.rs:331, a plain `for stage in stages` loop, and the
sibling products after them), so wall time = sum. CPU split over the whole process tree: frob 32%, rustfmt 19%,
cargo 16%, grimble sibling 12.5%, cargo-deny 6%, cargo-shear 6%, typos 5%. In frob itself: worktree
read+digest 9% (`gob_walk::content::ContentReader::read`), `link_calls` 6.7%, `SymbolGraph::build` 4%.
`graph_extracted: 283` and `file_hits: 3521` on EVERY warm run: 283 files are re-folded each time. H:
crates/gob-symbols/src/pipeline.rs:236 returns `fs.degraded` results before `cache.put_artifact`, so degraded
files (for example CHANGELOG-v1.md, 2.7 MB over the 2 MiB cap, which also logs a WARN on every run) are
never cached.
Cold stages (53 s under perf): walk 0.5, graph 5.8, directives 2.3, file-rules 12.9, repo:obligations 2.2,
repo:pm 2.3, repo:ledger 9.8, tools ~10, sibling:grimble 11.4. Parse/fold 28%, `snapshot::scan_one` 17%,
`ObligationFileCheck` 10%, `ledger_findings` 10% (frob-check/src/product.rs:140 = the same `Ledger::doctor` +
`home_path_findings` as `ticket doctor`, section 3.2). The grimble sibling is 29% of cold CPU: the second
product re-walks, re-reads, re-digests and re-parses the same 10.9k files.

### 3.7 Mutating verbs that are not slow

All `ticket` writes are 0.04-0.23 s (new 0.23, close 0.23, update 0.13, link 0.11, comment 0.11, evidence add 0.11,
triage 0.04-0.05); `ticket fragment`, `branch init`, `evidence fetch`, `config sync`, `init`, `lease widen`, `requeue`,
`work --here`, `release adopt/changelog` are 0.01-0.1 s. `frob work <ticket>` with a worktree is 2.0 s: 78% is the
`git worktree add` subprocess materialising ~10.9k files (inherent unless sparse), plus a 1.4-2.5 s gc pass
when the hourly throttle expires (`gc::pass::run` -> `referenced_digests`, section 3.2).

### 3.8 `frob land`: 452 s and 643 s (-vv timelines in `land.err`, `land2.err`)

Both runs show the same shape (seconds from start, run 1 / run 2):

| phase | run 1 | run 2 |
|---|---|---|
| merge base into ticket branch, then check pass 1 on the ticket branch (cold graph, sibling grimble 25 s / 14 s, `cargo clippy --all-targets` 68 s / 45 s, `cargo dev gen all --check` 115 s / 69 s) | 0 - 233 | 0 - 149 |
| check pass 2 (warm: tools 10 s, but 28 s of budgeted stages in run 2) | 236 - 258 | 150 - 191 |
| `git worktree add --detach` of the base for the ratchet, 5.3 s / 2.7 s | 258 - 264 | 191 - 197 |
| check pass 3 on the base checkout, "shares the worktree's build directory": clippy 61 s / 101 s, dev gen 72 s / 209 s, cargo-deny 6 s / 22 s | 264 - 438 | 197 - 605 |
| fast-forward base, land event commit, close ticket, release lease | 439 - 447 | 606 - 633 |
| `git worktree remove --force` of the ticket worktree (deletes ~2.7 GB target), 4.4 s / 8.7 s | 447 - 452 | 633 - 642 |

So: three full check pipelines (`gob_check::pipeline check finished` x3 with findings 1564, 1577, 1577; the
ratchet reported pre_existing 0, new 0, non_blocking 1564), of which two build the whole workspace from an empty
target dir: tools are 217 s + 10 s + 151 s of 452 s (run 1) and 132 s + 10 s + 358 s of 643 s (run 2). In the
primary, with a warm target, the same cargo steps take 1.6 s + 0.7 s + 0.5 s (section 3.6), so the cold target dir
per worktree is the multiplier, not the work. The base checkout is a different absolute path, so even though
`frob_land::ratchet::share_build_dir` (ratchet.rs:205) symlinks the worktree's `target/` into the base checkout, path-dependent fingerprints rebuild

reused). After the last check, the ledger side is another ~7-26 s: land event commit (`land event committed` at
+7 s / +12 s after the merge) and `close` (a further 1-14 s), both through `commit_events` + `synced()` full
index rebuilds (section 3.3). Code: crates/frob-land/src/land.rs, ratchet.rs, git.rs (worktree add/remove).

## 4. Cross-cutting causes, ranked by total impact

Impact = warm seconds saved across the command set measured here (sum over affected commands), plus the cold
and amplified costs where they dominate.

1. Per-file blob reads through a path walk (gob-git `read_blob_at`, `tree_of`, `rev_parse`; no gix object cache;
   loose objects inflated every time). Affects: ticket doctor, cycle velocity, board, doctor, doctor --languages, the
   gc pass of every verb once an hour, every cold ticket-index rebuild (about 30 verbs), `frob check` cold
   `repo:ledger` stage (9.8 s), land's post-check close (7-26 s), cycle/milestone/release writes (via 2).
   Roughly 25-30 s of warm single-command time, ~10 s of cold check, 7-26 s of land, and every number is x12 in the
   dev profile.
2. The ticket index is rebuilt in full, never patched: `Ledger::synced` (ledger.rs:666) rebuilds when the
   tickets-subtree key changes for any reason other than an in-process ticket write. Affects: plan --apply (7.4 s),
   assign/unassign/milestone add/release cut/bump (0.7-3 s), the first ticket read after any pm write, merge, pull or
   another agent's land (0.5-0.7 s release, 6-23 s dev/loaded). Fix 1 shrinks the constant; this removes it.
3. External tool stages serial; land runs the whole pipeline three times and builds from an empty cargo target dir in
   two fresh checkouts. Affects: `frob check` (tools are 5.99 s of 6.8-7.8 s warm, ~10 s of 53 s cold) and `frob
   land` (260-490 s of 452-643 s). Single biggest wall-clock item in the set.
4. Symbol-graph work that is uncached or duplicated: `frob test` (`Cache::null()`, 5.6-7.2 s every run), `grimble
   ack` (bind has no cache, 5.7-9 s and 1.35 GB), `frob ack` private `.frob/cache.sqlite` (cold per worktree),
   `link_calls` derived every run (23-26% of ack/graph), 283 degraded files re-folded on every warm check, Rust
   `scan_macro` nested parse (35-43% of any parse), three products each doing the same walk+read+parse.
   About 20 s of warm single-command time and ~25 s of the cold check.
5. The per-chunk worktree reader (`WorktreeSource::with_reader`, gob-git content.rs:144/53) opens the repository, the
   git index and a gix filter pipeline per rayon chunk, and files are hashed twice (sha1 for git-normalized
   content, blake3 for the walk digest). 25-65% of the warm profile of ack, graph, grimble check, crunk check,
   doctor --languages (about 0.3-0.6 s each) and 9% of warm frob check CPU.
6. Dev profile amplification: `[profile.dev]` leaves gix, zlib-rs, tree-sitter and toml at opt-level 0, only gob-ir is
   raised (Cargo.toml `[profile.dev.package.gob-ir]`). Measured: `ticket doable` cold 6.3 s (debug) vs 0.5 s
   (release); this is what makes the ledger path user-visible as "23 s".
7. Work done before validation (`grimble ack` binds 5-9 s and 1.35 GB then refuses) and verbs that always run the gc
   oracle (`frob doctor`, 0.8 s of which 93% is `referenced_digests`).
8. Observability gap: only `check` has `--timing`; every other verb needs `-vv` and perf to see stages, and `-vv`
   itself emits 120k-390k log lines per land/test.

## 5. Recommended fixes (would-be ticket titles)

1. "gob-git: read blobs by oid from one tree walk and enable the gix object cache"
   Scope: crates/gob-git/src/read.rs (`read_blob_at`, `tree_of`, `diff_names` to return blob oids; set
   `object_cache_size`), crates/frob-ledger/src/ledger.rs (`text`, `list_files`, `read_events_at`,
   `read_events_many_at`, `read_all_tickets`), privacy.rs/scrub.rs callers. Resolve `rev_parse` once per snapshot.
   Expected: ticket doctor 5-9 s -> under 0.5 s, velocity 2.2 -> ~0.1 s, board 1.9 -> ~0.1 s, doctor 0.84 -> ~0.1 s,
   cold index rebuild 0.5 s -> ~0.1 s, check cold `repo:ledger` 9.8 s -> ~1 s; the same 10x in debug builds.
2. "frob-ledger: sync the ticket index incrementally by tree diff"
   Scope: crates/frob-ledger/src/ledger.rs (`synced`), index.rs (upsert/delete by ticket path), key stored as
   tree id; pm writes (frob-pm store) update the key. Expected: first read after a pm write/merge/land
   0.5-0.7 s -> ~0.03 s; `cycle plan --apply` 7.4 s -> ~1 s; assign/unassign/milestone add 1 s -> ~0.1 s; land
   close steps -15 s.
3. "gob-check: run external tool stages concurrently with the in-process stages"
   Scope: crates/gob-check/src/tools.rs (`run_tools`), pipeline.rs; keep per-stage timing; cap concurrency (cargo
   stages share the target lock so group them). Expected: warm `frob check` 6.8 s -> ~2.5-3 s (limited by cargo fmt
   1.6 s + clippy + the file stages), cold -8 s.
4. "frob-land: one check pass, shared target dir, async worktree removal"
   Scope: crates/frob-land/src/land.rs, ratchet.rs, git.rs. Drop the second pass when the merge is a no-op, let the
   ratchet base check reuse the first pass result keyed by tree id (or share CARGO_TARGET_DIR with a stable path),
   and delete the ticket worktree in the background. Expected: land 450-640 s -> ~100-150 s (one cold build,
   ~3 s of git).
5. "frob-tests: use the shared repository cache and persist the touched-set graph"
   Scope: crates/frob-tests/src/touched.rs:64 (replace `Cache::null()` with the gob-cache shared handle).
   Expected: `frob test` planning 5.6-7.2 s -> ~1 s (same as warm ack).
6. "grimble-bind: cache per-file folds and build the U-term lazily"
   Scope: crates/grimble-bind/src/code.rs:102/143, crates/grimble-check/src/lib.rs:245 (`bind_repo`). Share the
   FileSymbols artifacts with frob (same `ArtifactKey`). Expected: `grimble ack` 5.7-9 s -> ~1 s, 1.35 GB -> a few
   hundred MB; grimble check cold 7.6 s -> ~1-2 s once frob has warmed the cache.
7. "frob-ack: open the repository-shared cache instead of .frob/cache.sqlite"
   Scope: crates/frob-ack/src/inputs.rs:147, rules.rs:453. Expected: ack on a fresh worktree 4.4-7 s -> 1.2 s.
8. "gob-symbols: persist the linked call graph and cache degraded files"
   Scope: crates/gob-symbols/src/graph.rs (`link_calls`, `resolve_site`), pipeline.rs:236 (cache the degraded
   result with a short marker). Expected: ack/graph warm 1.0-1.6 s -> ~0.5 s; 283 fewer re-folds per check.
9. "gob-walk/gob-git: one repository, index and filter pipeline per process; hash each file once"
   Scope: crates/gob-git/src/content.rs (`WorktreeSource::with_reader`, `WorktreeReader::read`),
   crates/gob-walk/src/content.rs. Expected: -25-65% on the warm runs of ack, graph, grimble check, crunk check,
   doctor --languages; -9% CPU on warm frob check; also halves the grimble sibling's walk cost.
10. "gob-symbols: stop re-parsing macro bodies with a second tree-sitter pass"
    Scope: crates/gob-symbols/src/rust.rs:1838 (`scan_macro`, `rest_group`, `macro_call`). Expected: 35-43% of any
    cold or uncached parse; cold `frob check` graph stage 5.8 s -> ~3.5 s.
11. "Cargo.toml: opt-level 3 for gix-*, zlib-rs, toml, tree-sitter in [profile.dev]"
    Scope: root Cargo.toml `[profile.dev.package.*]` (measured and rejected in the existing comment only for
    `package."*"` at 2; these four hot dependencies were not measured). Expected: debug `ticket doable` cold 6.3 s
    -> ~1 s, and the loaded-host 23 s case with it, for a few seconds of clean compile.
12. "frob-worktree/gc: make the oracle cheap and keep `frob doctor` from running a full pass"
    Scope: crates/frob-worktree/src/gc/glue.rs:39 (`referenced_digests`: batch with `events_many`, or index
    digests), gc/pass.rs, frob/src/doctor.rs:760 (skip the dry-run pass unless asked). Expected: doctor 0.84 s -> ~0.1 s; no 1.4-2.5 s hourly spike on `work`.
13. "grimble ack: validate arguments and preconditions before binding the repo"
    Scope: crates/grimble/src/ack.rs, grimble-check/src/lib.rs. Expected: error paths 5.7-9 s -> milliseconds.
14. "gob-cli: `--timing` on every verb (stage spans) and a perf profile job"
    Scope: gob-cli/gob-product verb wrapper, plus ticket ~RWD03DW's budget file. Expected: removes the need for
    perf to attribute time; keeps these regressions from returning.

Keep in mind the probes' caveats (shared, loaded aarch64 host; run-to-run +-30%); ranking and mechanisms
were consistent across independent runs and profiles, absolute seconds are not.
