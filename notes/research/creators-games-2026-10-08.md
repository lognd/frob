- Talks: 100 talk queries were run against YouTube (92 distinct video ids, 8 queries found nothing). Transcripts recovered: 0 of 92. YouTube answered HTTP 429 / 'sign in to confirm you are not a bot' to every request, first to my 100-query yt-dlp search batch, then to youtube-transcript-api. All 92 talks (including Acton CppCon 2014, Muratori Clean Code and Big OOPs, Blow talks, Overwatch ECS, Naughty Dog fibers video, Unite talks by Fine, Hipple, Dundore, Hodent, Swink, Juice it or lose it, Art of Screenshake) were therefore NOT read as transcripts. Mistake to disclose: my first retry loop had no backoff and sent about 81 transcript requests in a few minutes before I killed it; it did not use proxies or rotating clients. It was replaced by a paced loop (25 minute cool-down, then one request per 90 s doubling to 900 s, 3 hour cap) that I cancelled during its cool-down, before it sent any request, because the helper budget for extraction was spent; creators-games/loop2.py and yta.py resume it. Per the coordinator's instruction no evasion was attempted; the substitute was written equivalents: GDC Vault abstract pages, slides (Gyrling PDF), speakers' blogs, Game Programming Patterns (free online), Unity docs and e-book landing pages, Microsoft and JetBrains analyzer docs, press coverage of the TLOU2 accessibility talk. Where a talk is known only through a third-party write-up the item says so in the source list.
- Not obtained: Unity's PDF e-books (Performance, C# style guide, UI Toolkit; gated, only landing pages fetched, 0 items), Epic UMG performance page (fetch empty), Rider performance-indicator page, Maddy Thorson's physics write-up (403), Gamasutra postmortem index (404), Jason Gregory's book text, GDC Vault slide PDFs other than Gyrling's. Stance is extractor-assigned; I relabelled the 19 slugs that carry a genuine two-sided debate by hand (section 4.2) and treated 'against' on a smell slug as agreement with the lint elsewhere. No second labeller, so no kappa.

## 3. Taxonomy (step 3)

Same codes as the sibling (Mantyla and Lassenius 2009 with Beller 2014 extensions: EVO.*, FUN.*, TEST) plus UNITY.PERF, UNITY.LIFE, UNITY.SER, UNITY.ASYNC and UX.A11Y, UX.HUD, UX.INPUT, UX.FEEL. Tier vocabulary: syntax, structural, types, effects, human, plus render (needs rendered pixels or solved layout: contrast, text size, safe area, target size). Item fields: src, who, loc, para, mistake, reason, evid, lang, stance, cond, tax, norm, tier, conf, unity, hot (the lint matters only in per-frame code).

## 4. Consensus (step 3)

Method: items grouped by normalised slug (merged where the same lint), voices weighted per distinct person (PASS 1.0, PASS-W 0.5, organisations 1.0, unvetted 0), one voice per person per row (majority stance, ties become conditional). Score = flag + 0.5 cond - 1.5 oppose. Statuses: consensus-for (score >= 2.0, no opposition): 57; contested (hand-written two-sided rows): 14; thin (under 2.0 credible weight, mostly one analyzer or one doc page): 252; unweighted (only unvetted voices): 2. Most Unity rules are single-source-family (docs plus the two analyzer teams), so 'consensus' here measures independent tool vendors agreeing, not independent practitioner experience; only the Dunstan measurements and the Dundore talk summary add measured data.

### 5.4 Do not lint (taste, contested, version-bound or tool-owned)

- ECS versus OOP, enum-switch versus State classes, event bus versus direct calls, ScriptableObject architecture versus managers (C01, C09, C10): design choices with credible voices on both sides; at most an informational NEAT030-style size note.
- foreach over List<T> in Unity (C06) is version-bound: allocating on Mono before 5.6, free after; only the interface-typed variable still allocates. Lint the type, not the keyword.
- LINQ outside per-frame code (C07), manual inlining, and zero-allocation as a global target (C14): measured by Dunstan as acceptable when not a bottleneck; apply only under hot context and at informational severity (JetBrains' own stance).
- UNT0005 deltaTime-in-FixedUpdate (C13): retired upstream because Unity returns the fixed step there.
- Whole-screen colour-blind filters (C12): GAG advises against; lint the underlying colour-only signal instead.
- Juice and screenshake amounts, pacing and tutorial quality: human review (crunk human review lock), not syntax.
- C/C++ build-time rules (precompiled headers, unity builds, pragma once speed) from Llopis and Insomniac: Unity C# projects do not need them.

### 5.5 Already in frob-v2 per this evidence

- dotnet-unity.md 3: Unity messages are reach roots; [SerializeField]/public serialized fields have an external writer; SendMessage, Invoke(string), UnityEvent and string lookups are Unresolved dynamic calls; .meta/GUID hygiene. These make a hot-context rule and several suppressors feasible (the Microsoft suppressor list USP0003/0004/0006/0007/0008/0013 is the same set of false-positive guards).
- crunk.md 6 and 7: GX family, A11Y, CONTRAST, MOTION, LAYOUT target size, uGUI prefab audit of HudPrefabBuilder inputs, token mode stress.cb-safe.
- neatness.md: NEAT012 hidden-state-read (singleton, global state), NEAT004 nesting, NEAT030 thin-hook (applicable to fat Update bodies).
- Not in frob-v2: every Unity perf and correctness rule in 5.1, the paired-lifecycle rule, fixed-timestep misuse, input-legacy detection, Addressables vocabulary, asmdef file-format hygiene (project model only).

### 5.6 Meta-advice for the Unity pack

- Ship perf rules at informational severity gated by hot context, as JetBrains does; Microsoft's index marks UNT0021 (protected messages) opt-in and UNT0005 retired (default severities are not stated on the rule pages), and it publishes 23 suppressors for the stock IDE rules that Unity's runtime contradicts (unused private methods/fields that the engine or serializer uses, null-coalescing suggestions that break Unity null). A frob unity pack should carry both halves: rules and suppressions.
- Version gate: Find and foreach behaviour changed over Unity versions (FindObjectsByType replaces the obsolete FindObjectsOfType per the ScriptReference; List foreach stopped allocating in 5.6 per Dunstan); Camera.main is documented as costing about one GetComponent; the pack should read ProjectSettings/ProjectVersion.txt, which dotnet-unity.md already does for the editor.
- Measure claims: Dunstan's tables and Muratori's 1.5x to 15x are the only numeric performance evidence in the corpus; everything else is vendor authority.
