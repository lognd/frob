statement: every render element has exactly one plain-text shape -- the

criticality: medium

`frob.render._elements`'s module docstring (T-0448) claims every element
function produces exactly one plain-text shape: the sequence of characters
a plain-mode caller and a color-mode caller both produce, modulo ANSI
bytes. This is what lets `frob ... | tee` (or an agent capturing stdout)
see identical columns to a human at a color terminal -- if a color branch
ever inserted or removed a character (a different separator, an extra
space to visually balance an escape sequence) rather than only wrapping
existing text in escapes, plain-mode output would silently diverge from
what a human actually sees, defeating the "plain mode is canonical
machine-stable" design the whole render layer is built on.

`TestElementsPlainShapeInvariant` property-tests this directly with
Hypothesis across `heading`, `subhead`, `kv_row`, and `count_summary`:
for arbitrary text/mapping inputs, stripping `\x1b[...m` ANSI escapes from
the color-mode output must equal the plain-mode output exactly. This is
additive to the existing example-based
`TestElements::test_subhead_shape_identical_across_modes`, not a
replacement for it.
