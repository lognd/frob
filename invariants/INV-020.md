---
id: INV-020
statement: An explicit color-off signal (--no-color / --color=never /
  NO_COLOR / FROB_NO_COLOR) always beats CLICOLOR_FORCE and every other
  precedence level in resolve_color
criticality: medium
evidence:
  - tests/unit/test_render.py::TestResolveColor::test_no_color_flag_wins_over_everything
  - tests/unit/test_render.py::TestResolveColor::test_clicolor_force_colors_a_non_tty_stream
---

`resolve_color` checks its precedence levels in a fixed order: explicit
`--no-color`/`--color=never` first, then `--color=always`, then
`NO_COLOR`/`FROB_NO_COLOR`, then `CLICOLOR_FORCE`, then `TERM=dumb`,
finally the stream's own `isatty()`. Because the off-signals are checked
before `CLICOLOR_FORCE`, an explicit off always wins even when
`CLICOLOR_FORCE` is also set -- there is no code path where a later,
lower-precedence signal can override an earlier one.

`test_no_color_flag_wins_over_everything` sets multiple conflicting
signals at once (including a force-on one) and asserts the explicit-off
flag still wins; `test_clicolor_force_colors_a_non_tty_stream` proves the
positive case (CLICOLOR_FORCE alone, no conflicting off-signal, does
force color on a non-TTY), confirming the ordering is a real precedence
chain, not a coincidence of one test's inputs.
