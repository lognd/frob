id: INV-034
statement: Every reference resolves uniquely -- a node, flow, or secret id
  declared more than once in a module is always an elaboration-time
  DuplicateId error, never silently shadowed
criticality: medium
evidence:
  - tests/unit/strata/test_elaborate.py::TestElaborateValidation::test_duplicate_node_id_fails_closed
  - tests/unit/strata/test_elaborate.py::TestElaborateSecretAndDeploy::test_duplicate_secret_id_fails_closed
---

`_validate_no_duplicates` checks node, flow, and secret ids for
uniqueness within a module. The grammar itself has no notion of "already
declared" (two declarations sharing an id parse cleanly), so this is an
elaboration-level check -- but it runs unconditionally before a
`KernelModel` is built, and any duplicate id fails closed with
`Err(StrataError.DuplicateId)` rather than silently letting the later
declaration shadow the earlier one.

`test_duplicate_node_id_fails_closed` and `test_duplicate_secret_id_
fails_closed` each declare the same id twice for a different kind and
assert `elaborate` returns `DuplicateId`, not a silently-resolved single
declaration.
