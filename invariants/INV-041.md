`frob.gates._selfaudit_violations` (T-0756) is the ONLY path frob's own
self-conformance/resource-contention/reliability audit surface reaches
`frob check`'s gate pipeline through -- until this ticket, that surface was
reachable exclusively via the separate `frob sys audit` CLI verb, never a
`frob check`/`frob ticket land` gate. The root-cause incident this closes
(T-0724: a land reddened frob's own self-audit undisclosed) can only stay
closed if this fold is actually lossless: every violation the underlying
`frob.strata` checks report against a design model must surface as a
SELFAUDIT001 `Violation` in `sys_gate`'s output for that SAME model, with
no silent drop.

This is checked, not merely asserted: `test_selfaudit001_folds_selfconform_
violation` proves a genuine SYS100 finding (an observed-but-undeclared
capability) survives the fold as an ERROR-severity SELFAUDIT001 finding
naming the underlying rule id, through `sys_gate` itself (the production
entrypoint `frob check` calls) -- not through `check_self_conformance`
called directly. `test_selfaudit001_clean_model_no_violations` is the
before/after twin: the identical fixture, minus the undeclared-capability
gap, produces zero SELFAUDIT001 findings, proving the fold does not
manufacture false positives either.
