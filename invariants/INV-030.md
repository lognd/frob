---
id: INV-030
statement: A trust-lattice-scoped policy (on trust >= L) automatically
  covers every node at or above L in the trust lattice; a newly declared
  node at that level is in scope without re-declaring the policy
criticality: medium
evidence:
  - tests/unit/strata/test_policy.py::TestScopeResolution::test_trust_scope_resolves_via_lattice
  - tests/unit/strata/test_policy.py::TestScopeResolution::test_unknown_trust_level_fails_closed
---

`_resolve_trust_scope` resolves a `policy P on trust >= L { ... }` scope
declaration to every node whose trust level is at or above `L` in the
model's trust lattice (`model.trust.leq`), computed fresh from the
CURRENT node set every time policies are compiled -- there is no
snapshot or cache that would let a newly added `trusted` node miss a
pre-existing trust-scoped policy. Reorganizing which files back a
component does not change its trust level, so scope resolution is
unaffected by directory structure, only by the declared lattice
position.

`test_trust_scope_resolves_via_lattice` proves multiple nodes at/above
the declared threshold are all included; `test_unknown_trust_level_fails_
closed` proves an unresolvable trust level in the policy declaration is a
hard error rather than an empty (silently vacuous) scope.
