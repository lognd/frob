---
id: INV-007
statement: A `// BIND:` declaration with no matching native-side function
  declaration is always reported, never silently accepted
criticality: medium
evidence:
  - tests/unit/test_bind.py::test_check_reports_mismatch_for_unbound_binding
  - tests/unit/test_bind.py::test_scan_bindings_finds_cpp_and_rust
  - tests/unit/test_bind.py::test_scan_sources_finds_header_and_rust
---

`frob.bind.check` scans every `// BIND: <signature>` comment in pybind11/
PyO3 glue code (`scan_bindings`) and every native-side function declaration
(`scan_sources`), normalizes both signatures the same way, and reports a
`Mismatch` for any binding whose function name has no matching source
declaration. A Python-facing binding that drifts from (or never had) a
real native signature does not pass silently -- it is a lack-of-source
finding `frob bind` surfaces.

`test_check_reports_mismatch_for_unbound_binding` constructs a binding
with no corresponding source declaration and asserts `check` reports it;
the two scan tests prove both sides of the comparison (`scan_bindings`,
`scan_sources`) actually find their respective declarations across both
pybind11 (.cpp) and PyO3 (.rs) glue.
