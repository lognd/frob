---
id: INV-003
statement: The .frob/ cache is always rebuildable/derived -- it holds nothing that source cannot reproduce
criticality: medium
evidence:
  - tests/test_graph.py::TestLoadGraph::test_deleted_cache_is_rebuildable_from_source
  - tests/test_graph.py::TestCorruptCacheRecovery::test_garbage_cache_file_is_recreated
---

`.frob/cache.db` is a pure derived index over the working tree (per-file
content hashes plus parsed symbols/edges); nothing in it is authoritative.
Deleting it and re-running `build_graph` must reproduce the same snapshot,
never lose information, and never require a human recovery step -- this is
what makes it safe to gitignore and safe for CI to build fresh every run.

`test_deleted_cache_is_rebuildable_from_source` deletes `.frob/cache.db`
entirely after a first build and asserts a second `build_graph` call
against the same source tree succeeds and recovers the same symbol.

**Known gap** (tracked as T-0019, not yet fixed): a cache file that exists
but is not a valid sqlite database at all (as opposed to merely
wrong-schema) currently makes `build_graph` raise instead of transparently
rebuilding -- `cache.connect`'s DROP-TABLE fallback path assumes the
corrupt connection can still execute DDL, which is false for non-sqlite
bytes. The invariant holds for the "missing" and "wrong schema version"
cases (both handled by `cache.connect`'s existing rebuild path) but not yet
for "garbage bytes" corruption; T-0019 is the fix.
