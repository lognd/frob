---
id: INV-010
statement: An accepted decision record with no frob:decision code anchor
  is always a gate error (DEC002), never a silent gap
criticality: medium
evidence:
  - tests/test_decisions.py::test_dec002_accepted_decision_unanchored
  - tests/test_decisions.py::test_accepted_and_anchored_passes
---

`decisions/AD-###.md` records with `status: accepted` claim the record is
the current design and is actually implemented -- `_dec002` checks every
accepted decision id against `_anchored_decisions` (the set of ids with a
`frob:decision AD-###` edge somewhere in code) and raises a `DEC002`
`Violation` (ERROR severity) for any accepted decision with no anchor.
`proposed`/`superseded`/`deprecated` decisions are exempt (they are not
required to be anchored), matching the doc's stated rule that only
`accepted` carries the obligation.

`test_dec002_accepted_decision_unanchored` proves an accepted, unanchored
record fires DEC002; `test_accepted_and_anchored_passes` proves the
positive case (accepted + anchored) is silent, so the check is not merely
one-directional noise.
