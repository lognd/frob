id: INV-009
statement: parse_record never raises for a bad input file; every failure
  mode is a distinct typed Err, never a silent partial result
criticality: medium
evidence:
  - tests/unit/cve/test_parser.py::test_parse_missing_file
  - tests/unit/cve/test_parser.py::test_parse_truncated_json
  - tests/unit/cve/test_parser.py::test_parse_missing_required_field
  - tests/unit/cve/test_parser.py::test_iter_mirror_yields_records_and_errors
---

`frob.cve.parse_record` catches every failure mode a CVE Record Format v5
JSON file can present -- missing path, unreadable, malformed JSON, or a
structurally invalid record -- and returns a distinct `CveError` variant
(`NotFound`/`Unreadable`/`NotJson`/`MalformedRecord`) via a typani
`Result`, never letting `OSError`/`json.JSONDecodeError`/`ValidationError`
propagate to the caller. `iter_mirror` extends the same guarantee across a
whole mirror walk: a broken record is yielded as an `Err` alongside every
successful `Ok`, so a caller cannot mistake "silently skipped" for
"clean" -- it has to look at every yielded pair.

`test_parse_missing_file`, `test_parse_truncated_json`, and
`test_parse_missing_required_field` each drive one distinct failure mode
and assert a typed `Err` comes back with no exception escaping;
`test_iter_mirror_yields_records_and_errors` proves a mixed mirror (valid
+ broken records) yields both, not a silently filtered subset.
