statement: FROB_DISABLE_EXEC=1 genuinely stops every check-stage tool
  subprocess without spawning it; guarded_subprocess_run returns Err
  without ever calling subprocess.run when the kill switch is set
criticality: high
evidence:
  - tests/unit/test_process_guard.py::TestGuardedSubprocessRun::test_disabled_returns_err_without_spawning
  - tests/unit/test_process_guard.py::TestGuardedSubprocessRun::test_enabled_spawns_and_returns_ok
  - tests/unit/test_process_guard.py::TestCheckStagesHonorExecKillSwitch::test_run_ruff_disabled
---

`guarded_subprocess_run` checks `exec_enabled()` (false exactly when
`FROB_DISABLE_EXEC` is set truthy) BEFORE calling `subprocess.run` at all
-- when disabled it returns `Err(ProcessGuardError.ExecDisabled)` with no
process spawned. Every `frob check` tool-runner (ruff/ty/cmake/cargo/
clang-tidy/clang-format/ctest/npx-driven tsc/eslint/prettier/vitest)
routes through this guard, so the kill switch is a real, checked-in stop
for every subprocess `frob check` would otherwise spawn -- not just an
aspirational claim.

`test_disabled_returns_err_without_spawning` asserts no subprocess is
created when the switch is set; `test_enabled_spawns_and_returns_ok`
proves the positive case still works when unset;
`test_run_ruff_disabled` proves a real check-stage tool runner
(`_run_ruff`) honors the switch end to end, not just the guard function
in isolation.
