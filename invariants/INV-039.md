---
id: INV-039
statement: '_redact never returns the matched secret token itself in a
  SEC001/SEC002/SEC003 finding message -- only a provider-prefixed,
  length-annotated placeholder'
criticality: high
evidence:
  - tests/test_secrets_gate.py::TestRedact::test_never_returns_the_token
---

`frob.gates._secrets._redact` builds the human-readable text embedded in
every SEC001/SEC002/SEC003 violation message. If it ever leaked the actual
matched token substring, running `frob check` on a repo with a real
credential would print that credential into the gate's own diagnostic
output (terminal scrollback, CI logs, a JSON report artifact) -- the exact
opposite of what a secret-detection gate exists to prevent.

`_redact` returns a fixed shape instead: the caller-supplied prefix,
followed by `"... (N chars)"` where N is the original token's length --
enough for a human to recognize which provider matched and roughly how
long the leaked token was, without ever re-embedding the token bytes.

`TestRedact::test_never_returns_the_token` proves this against a
runtime-constructed token (deliberately never a contiguous literal in the
test file itself, per the file's own T-0190 GitHub-push-protection
discipline) and asserts both that the original token string is absent from
the output and that the output matches the exact redacted shape.
</content>
