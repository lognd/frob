---
id: INV-036
statement: A waive clause matches a finding only on an exact (node id,
  rule family, sub-target) triple -- it never suppresses a different
  sub-target on the same node and rule
criticality: high
evidence:
  - tests/unit/strata/test_litmus_waive.py::TestWaiveLitmus::test_sub_target_waiver_does_not_suppress_a_different_sub_target
  - tests/unit/strata/test_litmus_waive.py::TestWaiveLitmus::test_matched_waiver_suppresses_the_finding
---

`_split_kept_and_waived` indexes declared waivers by the exact `(node,
family, sub_target)` triple (`_index_declared_waivers`) and looks up each
finding by that same triple -- a waiver naming sub-target A can never
match a finding whose sub-target is B, even on the identical node and
rule family. This closes the "blanket waiver" failure mode: without
exact matching, a single `waive "RULE:A"` clause could silently suppress
every instance of `RULE` on that node regardless of sub-target.

`test_sub_target_waiver_does_not_suppress_a_different_sub_target` is the
T-0174 regression fixture: a node firing THREAT003 for two distinct CWEs,
with only one CWE waived -- asserting the OTHER CWE's finding still
fires unwaived. `test_matched_waiver_suppresses_the_finding` proves the
positive case (an exact match really does suppress).
