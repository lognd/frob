---
id: INV-021
statement: build_server registers exactly five tools, each a thin wrapper
  over an existing frob.graph/frob.tickets/frob.gates read path -- no
  mutating tool is exposed over MCP
criticality: medium
evidence:
  - tests/test_serve.py::TestBuildServer::test_registers_all_five_tools
  - tests/test_serve.py::TestDoableTickets::test_lists_queued_ticket
  - tests/test_serve.py::TestGraphQuery::test_resolves_symbol_and_edges
---

`build_server` registers a closed, named set of five tools --
`frob_doable_tickets`, `frob_stale_docs`, `frob_check_scope`,
`frob_graph_query`, `frob_doc_for` -- each of which calls straight into
`frob.serve._tools`, itself a thin wrapper around an existing read-only
`frob.graph`/`frob.tickets`/`frob.gates` query. There is no sixth,
mutating tool registered anywhere in `build_server`.

`test_registers_all_five_tools` asserts the registered tool-name set is
EXACTLY the five above, not a superset; the per-tool tests
(`TestDoableTickets`, `TestGraphQuery`, and their siblings) each exercise
one tool end to end over real fixture state and assert only query
results, never state changes, on that fixture -- consistent with every
registered tool being read-only.
