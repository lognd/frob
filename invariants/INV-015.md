---
id: INV-015
statement: A file with a tree-sitter-recoverable syntax error still yields
  every symbol tree-sitter could parse around the error, with a logged
  warning naming the loss -- ParseFailed is reserved for a totally
  unusable tree
criticality: medium
evidence:
  - tests/test_lang.py::TestErrors::test_syntax_error_yields_partial_symbols
  - tests/test_lang.py::TestErrors::test_syntax_error_logs_partial_tree_warning
---

`parse_file` (via `_parse`/`extract`) does not treat a tree-sitter
`has_error` tree as a hard failure: as long as the root node still has
children (a recoverable parse), it returns `Ok` with every symbol
tree-sitter could salvage around the broken region. `LangError.
ParseFailed` is reserved for the genuinely unusable case -- the root node
has an error AND no children. T-0434 (audit finding G9) required the
salvage path to also log a WARNING naming the file, so the lost tail of
the file is not a silent gap even though the overall result is `Ok`.

`test_syntax_error_yields_partial_symbols` parses a fixture with a broken
tail and asserts the symbol before the break (`good_one`) is still
extracted; `test_syntax_error_logs_partial_tree_warning` asserts the
salvage path logs the warning, so the loss is visible rather than a quiet
`Ok`.
