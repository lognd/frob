---
id: INV-031
statement: A domain trust declaration defaults to one-way; it is never
  silently treated as bidirectional -- the reverse edge is synthesized
  only when direction is explicitly declared two-way
criticality: medium
evidence:
  - tests/unit/strata/test_krb.py::TestKrbTrustFlows::test_sync
  - tests/unit/strata/test_krb.py::TestKrbTrustFlows::test_two_way_synthesizes_reverse_edge_too
---

`krb_trust_flows` synthesizes one `Flow` per declared `trusts` edge, and a
SECOND reverse-direction `Flow` only when the trust's `direction` is
explicitly `two-way`. A one-way (the default) trust declaration produces
exactly one flow in the declared direction -- there is no code path that
widens it to bidirectional without an explicit `direction "two-way"`
clause, matching charter law 2's "no security defaults" posture (an
implicit two-way trust would be a silent privilege widening).

`test_sync` declares a one-way trust and asserts exactly the single
forward flow is produced; `test_two_way_synthesizes_reverse_edge_too`
declares the same trust as two-way and asserts BOTH directions are
produced, proving the reverse edge is conditional on the explicit
declaration, not automatic.
